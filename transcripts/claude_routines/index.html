Executive Summary

Routines is a managed execution layer for Claude Code sessions that eliminates the infrastructure tax of building proactive agents. Three hard problems — hosting, triggering, and observability — are all solved by Anthropic's managed infrastructure. The three decisions that define every effective Routine: trigger type, context quality, and steerability approach.

🧱 The Problem: Why Proactive Agents Are Hard to Build Today

"We believe coding agents shouldn't wait for you to press enter to get started."

1. Where do agents run? Running on a local machine means if your laptop closes, the session dies. Building around this requires managing hosting, data persistence, and authentication — a substantial infrastructure investment before you write a single prompt.

2. When do agents trigger? Options today are cron jobs or custom webhook endpoints you spin up yourself. Both require ongoing infra maintenance.

3. How do you observe and steer them? Headless Claude Code sessions give no real-time visibility. There's no way to watch, steer, bound, or resume a running session.

💡 Key InsightThe gap between "reactive tool" and "proactive teammate" isn't a model capability gap — it's an infrastructure gap. The model can already do the work; what's missing is the scaffolding to trigger, host, and observe it reliably.

⚙️ Architecture & Capabilities

"It's an automation where you can kick off a remote Claude Code session by only defining the prompt, what repos you want to connect it to, what connectors it has available to work with, and a trigger. Claude Code handles the rest."

Always available: Routines run on Claude Code's managed infrastructure. Nothing depends on your laptop.

Two trigger types: Time-based (cron schedule) and event-based (GitHub native events or custom webhook POSTs).

Interactive and steerable: Every Routine is a regular Claude Code session — fully observable from web, CLI, or desktop.

🔗 ConnectionThe "just a Claude Code session under the hood" framing means all existing Claude Code capabilities — tool use, MCP connectors, repo access — are fully available. Routines adds scheduling and lifecycle management, not a new execution model.

Setup: Type /schedule → describe task in plain English → Claude asks clarifying questions → Routine created and visible in claude.ai web.

🎯 The Three Decisions

1. Trigger

Schedule-based (periodic, deterministic) or event-based (GitHub events, custom webhook). The event payload is passed as context to the Claude Code session.

💡 Key InsightThe event-based webhook trigger is underrated. ANY system that can fire a POST request can now initiate a Claude Code session with rich context — CI/CD, monitoring alerts, Zapier, Slack slash commands.

2. Context

The ceiling of Routine success is the ceiling of its context. Checklist: repos (read + write), external document stores, notification connectors (Slack, email), monitoring tools (Datadog, Grafana), domain-specific MCPs.

3. Steerability

Agent-on-agent review (Routine A generates, Routine B critiques); live oversight (type into running session mid-run); output verification (render/test Claude's outputs).

🔗 ConnectionGenerator-Critique Pattern: Routine A generates; Routine B critiques before human review. A native two-agent QA pipeline requiring no custom orchestration code.

🏗️ Real Use Cases

Use Case 1: Automated Documentation Sync (Anthropic Internal)

Routine A: Weekly Monday 10am schedule. Repos: Claude Code source + docs. Connectors: GitHub + Slack. Prompt: "Review changes merged to main, compare to docs, create PR if gaps found."

Routine B: issue.opened event trigger. Prompt: Investigate if it's a docs gap, if yes open a PR and ping Slack. Demo: Routine fires within seconds of issue creation.

Use Case 2: Deploy Verifier

Trigger: CD pipeline POST after every deploy. Context: source code + Datadog/Grafana + Slack/Twilio. Progression: Start → Claude gives go/no-go recommendation. Mid → human reads analysis, approves. Mature → Claude rolls back automatically, human notified post-facto.

"Maybe eventually as I watch Claude work more and more and trust its decisions, I can let Claude roll back the change itself."

Use Cases 3 & 4: On-Call Investigator / PM Backlog Reviewer

On-Call: Triggered by monitoring alert or schedule. Reads and triages backlog, prioritises, opens PRs for critical issues. PM Backlog: Weekly trigger. Reads all open issues, surfaces prioritised list.

💡 Key InsightEach use case follows the same three-question structure: What triggers it? What context does it need? How do I keep it honest? This is a portable "Routine Design Canvas" applicable to any recurring or event-driven workflow.

📜 AnalogThis mirrors how you onboard a junior engineer: pair-program first (watch), review their PRs (steer/review), then approve merges without reading every line (trust). The Routine earns autonomy through demonstrated reliability.

📋 Protocol Cheat Sheet

Creating a Routine

  • Run /schedule in Claude Code terminal
  • Describe task in plain English → answer Claude's questions
  • Routine appears in claude.ai web under Code → Routines

Trigger Types

  • Schedule: "Every Monday at 10am", "Daily at 9am"
  • GitHub events: issue.opened, pull_request.merged, push
  • Custom webhook: POST to Routine endpoint from any external system

Context Checklist

  • Repos (source + target, read + write)
  • External docs/files (Drive, Notion)
  • Notification connectors (Slack, email, Twilio)
  • Monitoring tools (Datadog, Grafana)

Quality Gates

  • Agent-on-agent review: second Routine triggered by first's PR
  • Live steering: open claude.ai web, type in session mid-run
  • Output verification: render/test outputs before closing loop
