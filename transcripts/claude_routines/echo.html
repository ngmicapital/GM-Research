Claude Code Routines: Proactive Agents Without the Infra Tax

👤 Maya · Anthropic Applied AI 🎓 Code with Claude Conference · ~22 min 🏷 AI Engineering / Developer Productivity

First-party (Anthropic employee demoing Anthropic product) — claims about internal usage stats are unverified externally.

⚡ The Bottom Line

  • Routines eliminates the DIY infrastructure tax for proactive Claude Code agents. No more managing cron jobs, hosting, auth, or session state — just define a prompt, repos, connectors, and trigger.
  • The shift is paradigmatic: agent-as-tool → agent-as-teammate. A tool waits for you. A teammate notices problems and acts on them.
  • Claude Code PRs at Anthropic are up 200% — and Routines was born from the resulting docs crisis. One engineer, exponentially more code changes.
  • Three decisions determine every Routine's effectiveness: what triggers it, what context it has, and how you steer it.
  • Agent-on-agent review is the recommended quality gate — one Routine generates output, a second Routine critiques it before any human reviews.

🔑 Key Claims

1
Live production use: Anthropic runs Routines internally to automate docs sync
Evidence: Sarah (Anthropic docs engineer) set up a weekly Routine that diffs Claude Code source vs. docs repo and opens PRs for gaps. Demonstrated live in the session.
Caveat: This is Anthropic using its own product — "eating your own dog food" credibility, but not a neutral third-party case.
2
Two trigger types: schedule-based and event-based (GitHub + custom webhook)
Evidence: Demoed both — a Monday 10am schedule routine and a GitHub issue.opened event routine — with live session kickoff visible in the UI.
Caveat: Webhook trigger requires your system to POST to the Routine endpoint; not fully no-code.
3
Every Routine is a standard Claude Code session — fully observable and steerable
Evidence: Mid-demo, Maya typed into a running Routine to stop it: "I've already made these changes." Session halted in real time. Observable from web, CLI, desktop.
Caveat: None flagged.
4
The generator-critique pattern (agent-on-agent review) is replicable as two Routines
Evidence: Described but not fully demoed. Routine A creates docs PR → triggers Routine B → B leaves review comments before human review.
Caveat: Quality of critique Routine depends entirely on prompt quality.
5
Context ceiling rule: Claude's success is bounded by the context it receives
Evidence: Direct quote. Emphasized specifically around connectors — repos, Drive, Slack, monitoring tools.
Caveat: None flagged; applies to all Claude deployments.
6
Progressive autonomy model: watch → steer → review → trust → delegate
Evidence: Deploy verifier use case walked through explicitly — human starts by reading Claude's analysis, eventually authorises Claude to roll back deploys independently.
Caveat: Timeframe for trust progression not quantified.
7
Setup is a single /schedule command in the Claude Code terminal
Evidence: Demoed live. Claude asks follow-up questions to clarify timing and notifications.
Caveat: None.
