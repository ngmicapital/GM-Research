Skills Beat MCP Alone: Supabase's Lessons from Writing the Hardest Document Since a Master's Thesis

SourcePedro Rodrigues · AI Engineer Conference
DomainAI Engineering / Developer Tools
Duration~18 min
SpeakerPedro Rodrigues, AI Tooling Engineer, Supabase
Full Mode

Executive Summary

  • Skills + MCP outperforms MCP alone on every model tested. Supabase ran evals across Claude (Opus 4.6, Sonnet 4.6) and OpenAI (GPT-5.4, GPT-5.4 mini). Skills won on test completeness every time, across every model.
  • The context gap is the problem, not intelligence. Agents using only MCP tools made critical security errors — failing to set SECURITY INVOKER=TRUE on Postgres views, silently exposing data. The skill prevented this.
  • "If something can get skipped, it will be skipped." Reference files are frequently ignored. Critical rules must live in SKILL.md body, not referenced files.
  • Don't duplicate documentation; point to it. Skills should direct agents to canonical sources, not reproduce them. Combine with directing agents to search aggressively.
  • Be opinionated in your skill. Encode optimal workflows explicitly. Supabase's schema management workflow (DDL → advisor → migration) prevents agents from creating migration files on every change.
  • Start minimal, iterate. Overloading a skill early is counterproductive. Build the minimum viable skill, measure via evals, expand.

🔑 The Core Problem — Stale Knowledge + No Guardrails

"We noticed that they would usually miss some security pitfalls… and they're very lazy and stubborn to admit that they don't know and do need to find fresh information." 02:08

Agents suffer from three failure modes on complex products: stale training data, security blindspots, and tool laziness (resisting web searches because they cost tokens).

The Postgres view vulnerability Rodrigues demonstrates: creating a SQL view over an RLS-protected table without SECURITY INVOKER = TRUE causes the view to bypass row-level security entirely, silently exposing all user data. An agent without skill context made this mistake; one with the skill did not.

🔍 Source Verified✅ Per PostgreSQL documentation, views execute with definer's privileges (usually superuser) by default. SECURITY INVOKER = TRUE (PostgreSQL 15+) makes the view execute with the caller's privileges, respecting RLS. Rodrigues' framing is accurate.
🎯 Against ConsensusStandard AI framing: "give the model more context and it will perform better." Rodrigues' finding is more specific: where you put the context matters as much as what you put there. SKILL.md body = always read; reference files = frequently skipped.

📂 Anatomy of a Skill — What Goes Where

Skills are folders with: SKILL.md (main file with front matter and instructions), scripts/ (executable helpers), and references/ (additional files — but often skipped).

Rodrigues' hierarchy of what gets read: SKILL.md body (always) → first reference file (sometimes) → second reference file (rarely) → third/fourth (essentially never).

💡 Key InsightThe reference file problem is a lazy loading anti-pattern. Agents optimise for token efficiency; every file read costs tokens. Any instruction you need the agent to always follow must be in the main skill body. Reference files are for "look this up if implementing X specifically."

🧪 How Supabase Tested the Skill — Evals on Markdown

"We're living in very interesting times where we can now test documents. I've basically been testing a markdown file." 11:00

Eval setup: 6 scenarios covering representative Supabase tasks · 4 agents: Claude Opus 4.6, Sonnet 4.6, GPT-5.4, GPT-5.4 mini · 3 conditions: baseline (no MCP, no skill), MCP only, MCP + skill · Scoring: completeness score (0–4), run on Braintrust.

Result: Skills + MCP outperformed on every model. The improvement was not model-specific — it was a universal signal that context/guidance is the binding constraint.

🌐 Consensus CheckEval frameworks for agent behavior (Braintrust, Langsmith, METR) are an emerging but rapidly solidifying practice. Testing documentation quality through agent performance represents the current state of the art in agentic QA.

🗂️ The SSH Docs Experiment

Supabase is exposing documentation through SSH, structured as a filesystem. Hypothesis: agents are deeply familiar with navigating Unix file trees. By exposing docs in that interface, agents can navigate documentation the way they navigate code repositories.

🔗 ConnectionSSH docs → agent-native infrastructure. This maps directly to Karpathy's complaint that documentation is still written for humans, not agents. Supabase is directly attacking that problem at the infrastructure level.

🏗️ The Opinionated Workflow — Schema Management

Supabase's encoded schema workflow:

  1. Run DDL freely on development/staging database
  2. When satisfied, run the Supabase Advisor (catches security + performance issues)
  3. Fix any advisor-flagged issues
  4. Only then create the migration file

Without this workflow encoded, agents create a migration file after every schema change, polluting version history. The skill enforces the correct discipline.

💡 Key InsightThis is the core value proposition of opinionated skills — they encode workflow knowledge, not just factual knowledge. An agent can know what RLS is without knowing that Supabase expects you to run the advisor before migrating. The latter is tribal knowledge that dies when you leave the team.

📋 Three Principles

Principle 1: Don't Duplicate Documentation

Point agents to your canonical source of truth. Don't reproduce docs inside the skill — they'll be stale immediately.

Add instructions telling agents where and how to find fresh documentation, and be persistent: the agent will default to training data unless you explicitly and firmly instruct otherwise.

Principle 2: If Something Can Be Skipped, It Will Be Skipped

Reference files are often ignored. Critical non-negotiable instructions must live in SKILL.md body.

The security checklist at Supabase was moved from a reference file to the main skill body after agents routinely missed it. The move made it impossible to skip.

Principle 3: Be Opinionated

You know your product's optimal workflows. Encode them. Don't let the agent guess.

Supabase's schema workflow (DDL → advisor → migration) is explicit and step-by-step. Without this, agents improvise suboptimal paths.

📋 Skill Writing Protocol

📋 Protocol Cheat Sheet
  • Critical security rules → SKILL.md body (never reference files)
  • Doc links → always include "where to find fresh docs" + insist agent goes to look
  • Be stubborn: explicitly and repeatedly tell the agent to search for current info
  • Encode your canonical workflow step-by-step (not just what, but how and in what order)
  • Start minimal, test via evals, iterate — don't overload on day 1
  • Reference files = "nice to have, usually skipped" — treat accordingly
  • Eval framework: Braintrust — test baseline, MCP-only, MCP+skill
