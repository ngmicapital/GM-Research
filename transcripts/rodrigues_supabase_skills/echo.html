Echo: Skills Beat MCP Alone — Supabase's Playbook


Source: Pedro Rodrigues · AI Engineer Conference · ~18 min

Domain: AI Engineering / Developer Tools · Content Type: Conference talk with live demo

Reliability: Data-backed — Braintrust evals across 4 models, 3 conditions, 6 scenarios

Mode: Full



⚡ The Bottom Line


  • **Skills + MCP beat MCP-only on every model tested.** Tested on Claude Opus 4.6, Sonnet 4.6, GPT-5.4, and GPT-5.4 mini. The advantage is model-agnostic.
  • **Agents skip reference files.** If something must always happen (e.g., security checklist), it must be in `SKILL.md` body, not a reference file. This is the most important practical lesson.
  • **Supabase found a real security bug from missing skill context.** Without skills, agents built Postgres views without `SECURITY INVOKER = TRUE`, silently bypassing row-level security and exposing all user data.
  • **The distribution problem is unsolved.** No universal skill registry exists. Repos, plugins, and platform-specific packages are fragmented.


    • 🔑 Key Claims (Ranked)


    1. Skills + MCP outperform MCP-only across all 4 models tested

    ↳ Evidence: Braintrust eval, 6 Supabase scenarios, completeness score grading

    ↳ Caveat: 6 scenarios is a small eval set; generalization requires more coverage

    ↳ Consensus: Aligned with emerging AI engineering best practices


    2. Agents frequently skip reference files in skill folders

    ↳ Evidence: Direct Supabase experience; moved security checklist from ref file to skill body after repeated misses

    ↳ Caveat: May vary by model and context length

    ↳ Consensus: Emerging — not widely published yet; this is practitioner knowledge


    3. Missing SECURITY INVOKER = TRUE on Postgres views over RLS tables exposes all data

    ↳ Evidence: PostgreSQL documentation confirms this behavior (default is SECURITY DEFINER)

    ↳ Caveat: Added in PostgreSQL 15; earlier versions have different mitigations

    ↳ Consensus: Confirmed ✅


    4. Skills are agent-agnostic (open standard, multiple platforms)

    ↳ Evidence: Claude Code, Cursor, and Windsurf all support skill-like CLAUDE.md/rules files

    ↳ Caveat: Formats differ across platforms; not fully standardized

    ↳ Consensus: Directionally correct


    5. Skill distribution is an unsolved problem

    ↳ Evidence: Rodrigues acknowledges no universal registry; multiple competing approaches

    ↳ Consensus: Correct as of mid-2025



    ⚡ Quick Actions


    | Protocol | Spec | When / Frequency | Key Detail |

    |---|---|---|---|

    | Security rules in main body | Put non-negotiable checks in `SKILL.md` body | Every skill write | Never in reference files |

    | Doc pointers over reproduction | Link to live docs, not copy | On every skill | Insist the agent goes to look |

    | Encode canonical workflow | Step-by-step in skill | For complex products | DDL → advisor → migrate (Supabase example) |

    | Eval with Braintrust | 6+ scenarios, 3 conditions | Before publishing skill | Baseline / MCP / MCP+skill |

    | Start minimal | Launch with only critical guidance | Day 1 | Iterate after measuring |
