Memory, Dreaming & Persistent Agent State

Ravi · Anthropic· Code with Claude Conference 2026·May 2026 Agent Infrastructure Memory Dreaming

Core argument: Agents that can't remember are stateless scripts. CMA introduces three primitives — persistent memory stores, dreaming (async synthesis), and optimistic concurrency — that enable agents to accumulate knowledge across sessions, synthesize insights without blocking the agent loop, and coordinate writes safely at scale.

Context & Stakes

Statelessness is the fundamental limitation of current LLM agents. Each new session starts cold. For enterprise agents handling legal research, incident response, or customer support, every re-learned fact is wasted compute. Ravi leads the API Knowledge team at Anthropic, building CMA's memory primitives in direct response to production pain from enterprise customers.

📡 Production Evidence

Rakuten: 97% error reduction. Harvey Law: 6× benchmark improvement on legal tasks via dreaming. Both are production deployments, not lab results.

Memory Stores

File-system-like persistent storage attached to CMA sessions. Agents interact via bash and grep — no special SDK. Stores persist across session boundaries: state accumulated in one session is available to the next, whether same agent or different agent in the same fleet.

💡 Insight

The filesystem metaphor is deliberate. Agents already understand file I/O. By mapping memory to this primitive, Anthropic eliminated the learning curve and made memory state trivially inspectable via standard tools.

Dreaming Architecture

Out-of-band batch process that synthesizes session transcripts into structured knowledge. The agent loop is never blocked. Flow: agent accumulates transcripts → dreaming job picks them up → Opus 4.7 synthesizes patterns and learnings → summaries written to memory store → next session starts enriched.

  • Non-destructive: original transcripts never modified
  • Idempotent: can be re-run without data loss
  • Async: no impact on agent response latency
⚠ Tradeoff

Dreaming introduces lag between experience and learned knowledge. For real-time learning, use hybrid: immediate writes + batch dreaming for synthesis.

Optimistic Concurrency

Multi-agent writes use version-check before commit. Protocol: read state + version → compute write → commit "if version still X" → on conflict, retry with updated state. Avoids locks, scales horizontally, and retries with better context.

💡 Implementation

~10 lines of code. Worth implementing in any custom memory system. Handles 95%+ of real-world multi-agent conflict scenarios without locking complexity.

SRE Demo: Alert Coordination

Fleet of SRE agents share an alert-coordination memory store. First agent to pick up an alert writes "investigating: [alert_id]". Others read before starting — see the claim, skip. Resolved incidents are documented back to memory. The fleet collectively builds institutional knowledge about incident patterns.

💡 Universal Pattern

"Claim before investigate" applies to any multi-agent system with potentially shared work items. Distributed coordination without lock complexity.

Implementation Patterns

Session Handoff

End of every session → write structured handoff: what was done, what failed, what's next. Next session reads first. Simple, immediate value.

Shared Fact Store

Multi-agent domain work → shared verified-fact store. Agents write discoveries, read before researching. Dreaming synthesizes for coherence.

Dreaming Pipeline

Nightly cron: input accumulated transcripts → Opus 4.7 synthesis → structured summaries in dedicated "synthesized" directory. Agents know synthesized > raw.

Strategic Implications

💡 Economics

Memory changes agent economics. Stateless agents have constant per-task cost. Memory-enabled agents amortize learning across all future tasks — they get cheaper per successful outcome over time.

🔁 Analog

Dreaming is to agents what sleep is to humans — compressing diffuse experience into structured long-term memory. Harvey's 6× didn't come from a better model; it came from organized prior work.

Decision Points

Dreaming vs real-time: Use dreaming when synthesis can be async (most cases). Real-time only when the agent needs the summary before its next action.

CMA vs custom memory: CMA for sub-agent observability + managed infra + built-in concurrency. Custom only for specific storage/latency requirements.
