Source: Lucas (Research PM, Anthropic) · Code with Claude Conference · ~21 min

⚡ The Bottom Line


  • **Scaffolding moved into the model.** Retry logic, tool routers, context compaction, coordinate math — these are now Claude's problem, not yours.
  • **Include output schema in tool descriptions.** Tell Claude what a tool returns, not just what it takes. Saves round trips, enables smarter planning. This is the highest-leverage tip in the talk.
  • **Context management is now config, not engineering.** 1M context + server-side compaction + context editing replaces entire custom memory systems.
  • **Computer use just got dramatically simpler.** Native 1440p screenshots, 1-to-1 pixel coordinates. Coordinate math is gone. OS World: 78% (above human average).
  • **Code that compensates for model unreliability has a half-life of months.** Build connectors to your world; leave reliability to Anthropic.


    • 🔑 Key Claims (Ranked)


    1. Tool routing accuracy is now high enough that heuristic pre-filtering makes things worse

    ↳ Evidence: First-party Anthropic claim; consistent with community reports on Claude tool selection

    ↳ Caveat: May not hold for very large tool sets (100+ tools)

    ↳ Consensus: Broadly aligned with 2025 practitioner experience


    2. Including tool output schema in description reduces round trips

    ↳ Evidence: Demonstrated via search_docs example (score field enables single-pass ranking)

    ↳ Caveat: Adds token overhead to the tool definition; tradeoff at scale

    ↳ Consensus: Novel tip, not yet widely documented — high practical value


    3. Opus 4.7 achieves 78% on OS World benchmark

    ↳ Evidence: Anthropic internal benchmark result; OS World is a legitimate public eval

    ↳ Caveat: Human baseline on OS World is ~72–75% — Claude is now at or above human level

    ↳ Consensus: Consistent with published SOTA; landmark result


    4. Server-side compaction + 1M context collapses custom memory systems

    ↳ Evidence: Anthropic API feature — verifiable

    ↳ Caveat: 1M context at "flat pricing" — pricing details matter for cost-sensitive apps

    ↳ Consensus: Confirmed feature


    5. Any code compensating for model unreliability has a half-life of months

    ↳ Evidence: Historical pattern of Anthropic absorbing scaffolding into the model

    ↳ Caveat: Prediction about future releases; directionally reliable

    ↳ Consensus: Widely believed in AI engineering community



    ⚡ Quick Actions


    | Protocol | Spec | When / Frequency | Key Detail |

    |---|---|---|---|

    | Output schema in tool description | Add `Returns: {field: type}` to description | Every new tool | Enables planning without round trip |

    | Remove tool router | Pass all tools, no pre-filtering | Immediately | Router degrades performance now |

    | Clear stale tool results | Delete screenshots/file reads after each turn | Every end-turn | Keep decisions, not raw results |

    | /context in Claude Code | Run to see color-coded context breakdown | When context feels heavy | Shows messages, tools, system, MCP usage |

    | Test image formats for computer use | Try JPEG, PNG, WebP at your resolution | When implementing computer use | Different UIs compress differently |

    | Pre/post tool hooks | Define in claude_settings.json | Security-sensitive workflows | Block or log tool calls programmatically |

    | /schedule in Claude Code | Set cron for autonomous runs | Recurring tasks | Write-run-fix loop on a timer |
