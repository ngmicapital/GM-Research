⚡ The Bottom Line


  • **December 2024 was a phase transition.** Agentic workflows stopped failing in patches and became reliably end-to-end capable. This is not incremental.
  • **Software 3.0 invalidates entire app categories.** If a neural net can do a transformation directly (photo → annotated image), an app that breaks it into coded steps is the wrong abstraction.
  • **Vibe coding ≠ agentic engineering.** Vibe coding raises the floor for everyone. Agentic engineering preserves professional quality while going faster. They are different disciplines.
  • **"You can outsource your thinking, but you can't outsource your understanding."** The human remains the bottleneck for judgment, direction, taste, and system-level oversight.
  • **LLMs are ghosts, not animals.** Calibrate accordingly: no intrinsic motivation, no genuine curiosity, no self-preservation. Statistical simulation shaped by training choices you can't see.


    • 🔑 Key Claims (Ranked)


    1. LLMs represent a new computing paradigm (Software 3.0), not faster Software 1.0

    ↳ Evidence: MenuGen example — the entire app is superseded by a prompt; OpenClaw installation as natural language paste

    ↳ Caveat: Many tasks still require Software 1.0 determinism (payments, file I/O, APIs)

    ↳ Consensus: Influential framing; contested in research circles, widely accepted by practitioners


    2. Jagged intelligence is diagnostic: capability = verifiability + lab training choices

    ↳ Evidence: Car-wash paradox; chess capability jump from pre-training data curation

    ↳ Caveat: Labs are actively working to close the common-sense gaps

    ↳ Consensus: Partially aligned — "jaggedness" is acknowledged; mechanism debate ongoing


    3. December 2024 marked a qualitative shift in agentic coherence

    ↳ Evidence: Karpathy's personal experience; corroborated by community-wide reports at the time

    ↳ Caveat: Anecdotal; no controlled study

    ↳ Consensus: Widely reported — Claude Sonnet / GPT-4o improvements cited by many practitioners


    4. Humans must retain understanding even as agents handle execution

    ↳ Evidence: MenuGen user ID bug — agent made reasonable but wrong assumption that human would have caught

    ↳ Caveat: As models improve, the "understanding required" threshold may lower

    ↳ Consensus: Current consensus aligns; contested at AGI frontier


    5. Current hiring processes don't test agentic engineering skill

    ↳ Evidence: LeetCode puzzles test pre-agentic programming; no eval of agent coordination, spec design, or oversight

    ↳ Consensus: Emerging — companies haven't broadly updated hiring rubrics


    6. Agentic engineering speedups exceed the "10x engineer" framing

    ↳ Evidence: Karpathy's observation from his own practice; no empirical study cited

    ↳ Consensus: Widely believed in AI engineering community; not empirically measured



    ⚡ Quick Actions


    | Protocol | Spec | When / Frequency | Key Detail |

    |---|---|---|---|

    | Write spec before delegating | Document system design + data model before agent starts | Every new project | Agents will make wrong assumptions (e.g., email-based user ID) |

    | Probe for domain valleys | Ask model edge-case/common-sense questions in your domain | Before production | Find the car-wash failures before users do |

    | Build personal knowledge base | LLM-synthesized wiki from articles you read | Ongoing | Multiple projections onto data = accelerated understanding |

    | Agent-native docs | Structure context as "what to paste to agent" not "what to read" | Infrastructure decisions | Shift from human-readable to agent-readable |

    | Red-team hired candidates | Give large project; attack deployed result with agents | Hiring | Test agentic engineering, not puzzle-solving |
