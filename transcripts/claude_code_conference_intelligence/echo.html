Claude Code Routines: Proactive Agents Without the Infra Tax

SourceMaya, Anthropic Applied AI · ~22 min
DomainAI Engineering / Developer Productivity
ReliabilityFirst-party Anthropic demo — credible on product, unverified on internal stats
Content TypeProduct demo + workshop
Full Mode

⚡ The Bottom Line

  • Routines eliminates the DIY infrastructure tax for proactive Claude Code agents. No more cron jobs, hosting, auth, or session state — define a prompt, repos, connectors, and trigger. Done.
  • The paradigm shifts: agent-as-tool → agent-as-teammate. A tool waits for you. A teammate notices problems and acts on them.
  • Claude Code PRs at Anthropic are up 200% — Routines was born from the resulting docs crisis. One engineer, exponentially more code changes.
  • Three decisions define every Routine: trigger (when), context (what Claude knows), steerability (how you stay honest).
  • Agent-on-agent review is the recommended quality gate. One Routine generates; a second Routine critiques before any human reviews.

🔑 Key Claims (Ranked)

1. Anthropic runs Routines internally — live docs sync automation

↳ Evidence: Weekly Routine diffs Claude Code source vs. docs repo, opens PRs for gaps. Demoed live.
↳ Caveat: Anthropic using its own product — credible but not a neutral third party.

2. Two trigger types: schedule-based and event-based (GitHub native + custom webhook)

↳ Evidence: Both demoed live — Monday 10am schedule and issue.opened event Routine.
↳ Caveat: Custom webhook requires your system to POST to the Routine endpoint.

3. Every Routine is a standard Claude Code session — fully observable and steerable

↳ Evidence: Mid-demo, Maya typed into a running session to stop it in real time. Works from web, CLI, desktop.

4. Agent-on-agent review replicable as two Routines (generator-critique pattern)

↳ Routine A creates PR → triggers Routine B → B leaves review comments before human review.
↳ Caveat: Critique quality depends entirely on prompt quality.

5. Context ceiling: Claude's success is bounded by its context

"Whatever context Claude has, that's the ceiling of how successful Claude will be." 11:46

6. Progressive autonomy: watch → steer → review → trust → delegate

↳ Deploy verifier use case — human starts reviewing Claude's output, eventually authorises autonomous rollback.

7. Setup is a single /schedule command

↳ Claude asks follow-up questions, generates structured instructions, creates the Routine automatically.

Man Group: Skills Governance Is the Enterprise AI Moat

SourceTashara Fernando, Head of Data & AI, Man Group · ~20 min
DomainEnterprise AI / Agentic Systems / Quant Finance
ReliabilityFirst-party practitioner, live production with real capital. High credibility.
Content TypeExecutive case study + practitioner lessons
Full Mode

⚡ The Bottom Line

  • AI-generated trading signals are in live production at Man Group, running real pension capital. Full pipeline — idea → data → backtest → proposal → productionisation — AI-driven, human-reviewed.
  • The signal is easy. The governed workflows beneath it are the moat. Shared backtest infrastructure makes results comparable. Without it, you can't trust your own signals.
  • Man Group learned governance the hard way. Power users, not process owners, built early skills. Local optimisations spread org-wide. Required a complete governance rebuild.
  • Skills governance — not adoption — is the enterprise AI unlock. A library with ownership, testing, lifecycle, and visibility is the foundation for everything else.
  • Your organisational context is your AI moat. Frontier labs cannot give it to you. The work is exposing what you already know, not reinventing it.

🔑 Key Claims (Ranked)

1. AI-driven trading signals live in production at a regulated $200B AUM investment firm

↳ Evidence: Fernando states directly; full pipeline described. Humans reviewed but AI was "at the centre of the process."
↳ Caveat: Specific signal, returns, and asset class not disclosed — proprietary IP.
↳ Consensus: Contrarian in degree of automation; full-pipeline AI ownership is at the frontier.

2. The iceberg problem: shared workflows make results comparable

"Think of it like an iceberg. The signal is the tip. Underneath it are all of the workflows that make it possible." 06:24

3. Power users, not process owners, build the first wave of skills — that's the problem

↳ Evidence: Expense report story — cost centre hardcoded to one user, distributed org-wide, wrong approval routing. Audience recognition confirmed.

4. 750 of ~1,700 Man Group employees use Claude Code (44% of the firm)

↳ Spans developers, quants, people team, finance team. 100+ governed skills, 100+ community skills.

5. Credit card spend signal: $1K in 2021 → ~$2,500 now

↳ Caveat: Illustrative demo case; in-sample backtest only. Not actual Man Group trading performance.

6. Frontier labs will not solve your organisational context

"The frontier labs are not going to solve context for you. It's not on the internet. They don't know your workflows. And you already have that context. You have decades of it. The work is on exposing it, not reinventing it." 16:59

7. Plan governance before rollout

"Decide this before shipping the first skill, not after the hundredth like us." 17:39
