Core reframe: Stop optimizing for cheapest token. Optimize for cheapest per successful outcome. Opus 4.7 is often faster and cheaper than Sonnet on complex tasks because it succeeds in fewer attempts. Prompt caching to 80-90% hit rate cuts costs by 10×. Context engineering — cleaning tool responses and deduplicating search results — reduces input tokens by 66-77% with accuracy gains. These aren't incremental improvements; they're order-of-magnitude economics.

Decision Framework: Model Selection

Step 1: Define what "success" means for your task (correct answer, no hallucination, specific format)

Step 2: Measure success rate per model on your actual task distribution

Step 3: Calculate cost per successful outcome = (token cost) / (success rate)

Step 4: Opus 4.7 often wins on step 3 for complex tasks despite higher per-token cost

Prompt Caching Playbook

  1. Use append-only message patterns — never modify earlier turns in the conversation
  2. Put stable content (system prompts, reference docs) first in context
  3. Put dynamic content (user input, tool results) last
  4. Target 80-90% hit rate; below 60% means your cache prefix is changing too often
  5. Monitor cache hit rate as a production metric — it's directly correlated to cost

Context Engineering Wins

💡 Quick Win #1

Tool response format: Return markdown instead of JSON. 66.4% token reduction. Model comprehension improves. Zero accuracy cost.

💡 Quick Win #2

Deduplicate web search results: Multiple searches often return overlapping content. Dedup before injecting into context → 77% input reduction, 65% cost reduction, 9% accuracy gain (fewer contradictory signals confuse the model).

Thinking vs Effort Parameters

Thinking: Raw parameter controlling reasoning depth. Higher = more compute, better on complex multi-step problems.

Effort: Higher-level abstraction over thinking tokens. Maps human intuition ("try harder") to the right thinking budget automatically.

When to use which: Effort for most applications (simpler to tune). Thinking for fine-grained control when you know your task's compute requirements.

Actions

  1. Reframe your cost metric: track cost-per-successful-outcome, not cost-per-token
  2. A/B test Opus 4.7 vs Sonnet on your hardest tasks — you may be surprised which wins on economics
  3. Audit your tool response formats — JSON → markdown is an immediate 66%+ token reduction
  4. Add web search deduplication before context injection
  5. Implement append-only message patterns and monitor cache hit rate
  6. Set cache hit rate target of 80-90% as a production engineering goal
