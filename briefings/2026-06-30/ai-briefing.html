⚡ Update: GPT-5.6 Sol — Terminal-Bench 2.1 SOTA, ultra mode detail

Limited Preview

GPT-5.6 Sol, Terra, and Luna — announced June 26 — now have confirmed benchmark placement: Sol sets a new state-of-the-art on Terminal-Bench 2.1, the command-line workflow benchmark that rewards planning, iteration, and tool coordination over single-shot code generation. Sol's new ultra mode routes hard sub-tasks to specialized subagents, effectively turning a single model call into a lightweight multi-agent pipeline. Pricing locked at $5 input / $30 output per 1M tokens for Sol; Terra at $2.50/$15; Luna at $1/$6. API access remains limited preview — broad availability not yet dated.

Terminal-Bench 2.1 is one of the four benchmarks that actually separates frontier models in 2026 (alongside GPQA Diamond, Humanity's Last Exam, and SWE-bench Pro) because it resists data contamination. Sol topping it means the lead in real agentic shells is real, not leaderboard positioning. Watch for third-party reproductions before updating infrastructure decisions.

GLM-5.2 — 62.1 SWE-bench Pro at $1.40/M input

Benchmark

Zhipu AI's GLM-5.2 (released June 13, open-weight MIT license) posts 62.1% on SWE-bench Pro — above GPT-5.5 (58.6%) and MiniMax M3 (59.0%), behind only Claude Opus 4.8 (69.2%) among verified public runs. Specs: 744B total / 40B active MoE, 1M-token context. Cost via OpenRouter: ~$1.40/M input, $4.40/M output — approximately 3.5× cheaper than Sol for comparable coding tasks. The model is the first Chinese AI to rank top-three globally on a major coding benchmark by independent evaluation.

At $1.40/M input GLM-5.2 is the price-performance anomaly of Q2 2026. For coding pipelines that don't need Opus 4.8's reasoning depth, this reprices the conversation. The MIT license matters: production fine-tuning is permitted without a separate commercial agreement.

Kimi K2.7 Code — 1T-param MoE, 30% fewer reasoning tokens

Open Weight

Moonshot AI's Kimi K2.7 Code (released June 12) delivers 35.1 on MLS Bench Lite (vs GPT-5.5's 35.5), with a ~30% reduction in reasoning-token consumption vs K2.6. Architecture: ~1T total / 32B active parameters, 256K context. Positioned as the speed/cost play for software engineering pipelines that need K2.6 class output at lower inference cost. Commercial-friendly license.

The underlying pattern in trending repos: frameworks that solve the long-running autonomous workflow problem (execution loops, multi-agent delegation, checkpoint-resume) are growing faster than model wrapper libraries. DeepSeek V4 and Qwen 3.6 27B are the most-forked base models by the community building on top of these frameworks.

Research Radar

This week's papers converge on agent memory as the limiting factor for long-horizon tasks — not model intelligence.

Memory for Autonomous LLM Agents: Mechanisms, Evaluation, and Emerging Frontiers (arXiv:2603.07670)

Pengfei Du's survey organizes agent memory systems along three axes: temporal scope, representational substrate, and control policy. Five mechanism families are analyzed: context-resident compression, retrieval-augmented stores, reflective self-improvement, hierarchical virtual context, and policy-learned management. The key methodological shift is in evaluation: the paper argues static recall benchmarks are insufficient and proposes multi-session agentic tests that interleave memory with decision-making as the right measurement unit. Five open challenges remain unsolved: continual consolidation (updating memory without catastrophic forgetting), causally grounded retrieval (knowing which past event caused a current state), trustworthy reflection (self-evaluation without hallucination), learned forgetting (deciding what to drop), and multimodal embodied memory.

Practical signal: if you're building agents that run across sessions, the paper's framework is a useful checklist. Most production agent stacks handle episodic retrieval adequately but fail on causally grounded retrieval and trustworthy reflection — the two gaps that produce "confident but wrong" long-horizon agents.

International AI Safety Report 2026 (arXiv:2602.21012) — capability risk synthesis

The 100+ expert report mandated from the Bletchley AI Safety Summit synthesizes evidence on capabilities, emerging risks, and safety of general-purpose AI systems across 29 nations plus UN/OECD/EU. The report's key structural finding (widely cited in June): the gap between what frontier models can do in controlled evals and what they do reliably in production is the primary unsolved safety problem — not existential risk abstraction. This has direct implications for the "deployment simulation" evaluation frameworks gaining traction in 2026. Singapore Consensus (arXiv:2506.20702, covered in prior issue) built on this framing; the Safety Report is the evidence base.
