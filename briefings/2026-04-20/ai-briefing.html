[Fundamentals]

How AI Benchmarks Are Designed — And Why They Get Gamed

Every model release in April 2026 has arrived with a benchmark table. GPT-6's unverified leaks claim 95%+ HumanEval. Opus 4.7 posts 87.6% SWE-bench. Understanding how these numbers are produced changes how much you should trust them — and when to discount them entirely.

A benchmark is just a dataset of questions with known answers, run against a model in a controlled setting. The model's score is the percentage it gets right. Simple in concept. The problems start immediately. First: contamination. If the benchmark's questions appear anywhere in the model's training data, the model is effectively memorising answers rather than demonstrating reasoning. Every major lab is suspected of having trained on some benchmark data, intentionally or not. When a new benchmark appears, scores are initially high — because the questions are novel. Over 12–18 months, as the benchmark gets widely discussed, training data incorporates it and scores converge upward without genuine capability gain.

Second: benchmark selection bias. Labs publish the benchmarks where their model does best and bury the others. OpenAI publishes MMLU and HumanEval; Google publishes scientific reasoning benchmarks; Anthropic publishes coding benchmarks. The choice of what to feature tells you as much as the score itself. SWE-bench, GPQA, and CursorBench are harder to game because they require multi-step reasoning in real environments rather than multiple-choice answers.

Third: evaluation methodology matters enormously. SWE-bench "Verified" (the version Anthropic uses) was human-vetted to remove ambiguous or broken test cases. The unverified version has much lower scores across all models. When comparing benchmarks across labs, check whether they're using the same evaluation methodology — a 5% gap between models often disappears when you standardise the evaluation setup.

Why this matters for the AI landscape: The benchmark arms race has produced numbers that are increasingly disconnected from real-world task performance. The most reliable signal is not the score but whether a benchmark is new (harder to game), human-verified (ambiguity removed), and task-realistic (measures multi-step work in actual environments, not trivia). CursorBench and SWE-bench Verified are the current gold standard. MMLU and HumanEval are essentially gamed — treat them as vanity metrics.

[Launch]

Hermes Agent v0.10 — The First Open-Source Closed Learning Loop

Nous Research shipped Hermes Agent v0.10 on April 16, and the core innovation is not another agent framework — it's the first open-source implementation of a genuine closed learning loop. The mechanism: after any task requiring 5+ tool calls, Hermes automatically writes a "skill document" capturing what it did and how. Skills are stored in a SQLite + FTS5 store with sub-10ms retrieval even across 10,000+ documents. When a similar task fires next time, the relevant skill is loaded and the agent doesn't start from scratch.

v0.10 ships with 118 pre-built skills, three-layer memory (session context + persistent SQLite store + drift-adjusting user model), and six messaging integrations including Telegram. The result: self-created skills cut research task time by 40% vs a fresh agent instance. Star count: 47K+ stars in under two months since public release. MIT licence.

Architecture note: the three-layer memory design mirrors what enterprise AI memory systems do ($100K+/yr tools) — the difference is that Hermes does it in a local SQLite file with zero cloud dependency. The user model layer adapts to dc's workflow patterns over time, not just to individual task types.

Try Today

Install Hermes Agent and run it on a research task you repeat weekly — e.g., "pull the top AI tokens by dTR from the Wyckoff Scanner and summarise." Let it generate a skill document on the first run. Run the same task 3 days later and compare: the skill should cut setup time and improve output structure. The persistent memory across sessions is the feature worth evaluating — it's the most credible free alternative to Claude Code's cross-session context limitations.

Hermes is the first open-source agent worth running alongside Claude Code rather than instead of it — the use case is structured repeatable research tasks where skill accumulation compounds. [Fundamentals]

How HuggingFace Works — The Infrastructure Layer the Whole Ecosystem Runs On

Hermes Agent shares skills through HuggingFace. Llama 4 Maverick was released on HuggingFace hours after Meta's announcement. Every open-source benchmark comparison links to HuggingFace model cards. Understanding what HuggingFace actually is — and why it became this central — makes the open-source AI news far more legible.

HuggingFace started as a chatbot company in 2016, pivoted in 2019 to host the Transformers library — an open-source Python package that wrapped every major pre-trained model in a standardised interface. Instead of each lab releasing models in incompatible formats with custom loading code, Transformers gave the community a single API: from_pretrained("model-name") — load any supported model in one line. The ecosystem consolidated around this because the friction reduction was enormous.

Today HuggingFace is four distinct things at once: a model hub (750K+ model repositories, versioned weights, model cards with documentation); a dataset hub (100K+ datasets in standardised formats); an inference API (run any hosted model via HTTP without local hardware); and a Spaces platform (host interactive ML demos in Gradio or Streamlit, free tier included). The infrastructure is git-based — every model is a git repo with large file support, branching, and version history.

The business model is straightforward: the hub and most tooling are free. Revenue comes from Enterprise Hub (private model hosting with access controls, SSO, audit logs) and Inference API compute at scale. This makes HuggingFace structurally different from other AI platforms — it has genuine open-source community incentives rather than purely commercial ones, because the more useful the free tier, the more enterprise customers adopt it.

Why this matters for the AI landscape: HuggingFace is the connective tissue between labs and developers. When a lab releases a new model, it ships to HuggingFace simultaneously — sometimes hours before the blog post — because that's where the developer community will pull it from. When fine-tuning techniques like LoRA improve, HuggingFace's PEFT library makes them accessible within days. And when community skill packs or model adapters emerge (as with Hermes), HuggingFace becomes the distribution mechanism. The health of the open-source AI ecosystem is directly proportional to the health of HuggingFace as a neutral infrastructure layer.

New York RAISE Act — Frontier AI Transparency Law, Effective January 1, 2027

Governor Hochul signed the New York RAISE Act (Responsible AI Safety and Education Act) on March 27, 2026. This is a separate and distinct law from the federal RAISE Act covered in Issue #23 — New York's version is a state-level framework with specific requirements and penalty structures that go beyond the federal rules.

Key requirements: frontier developers must publish a transparency report before deploying any new frontier model — including release date, supported languages, output modalities, intended uses, and restrictions. A new AI oversight office within the Department of Financial Services will assess large frontier developers annually. 72-hour incident reporting obligation: any qualifying safety incident must be disclosed to the state within three days of determination. Penalty structure: $1M initial violation, $3M subsequent violations. Effective date: January 1, 2027 — 8 months from today.

The law applies to frontier models "developed, deployed, or operating" in New York — which captures OpenAI, Anthropic, Google, Meta, and xAI by definition. The DFS oversight mechanism is novel: financial services regulators, not a new AI agency, will have enforcement authority. This gives the law teeth immediately (DFS has existing investigative and enforcement infrastructure) rather than waiting for a new regulatory body to build capacity.

The tension with the White House National Policy Framework: the Trump Administration's March 20 Framework recommends federal preemption of state AI laws. If Congress acts on that recommendation, New York's RAISE Act may be overridden — but that legislative fight will take 12–18 months minimum. Labs are treating January 1, 2027 as a real compliance deadline regardless.

Market-level signal. The 8-month compliance window means every major lab is now in active disclosure preparation. For dc: no direct trading action, but frontier labs with heavy New York business exposure (all of them) face a hard transparency deadline that will force more detailed model release documentation. The annual DFS assessment creates a recurring accountability cycle.

Research Radar

Papers that become products in 6 months
AI Scientist-v2 crossed the peer review threshold — an AI-written paper accepted at a workshop through normal review — which makes autonomous scientific research infrastructure, not a demo.
AI Scientist-v2: Workshop-Level Autonomous Scientific Discovery via Agentic Tree Search
Sakana AI · April 2026 · arXiv:2604.XXXXX

One-line finding: An AI system autonomously proposes hypotheses, runs experiments, analyses results, and writes a paper — and one of those papers was accepted at a major workshop through the standard double-blind peer review process.

The leap from v1 to v2 is the tree search architecture. V1 generated papers in a linear pipeline; v2 explores a tree of experimental directions, pruning low-signal branches and investing more compute in promising ones. This is the same structural shift from greedy decoding to beam search in language models — it finds higher-quality outputs by exploring the solution space rather than committing to the first coherent path.

Why it matters in 6 months: Workshop acceptance through blind peer review is the threshold that separates "impressive demo" from "usable research infrastructure." Labs running large-scale hypothesis testing — drug discovery, materials science, financial market structure research — now have a proof-of-concept that AI-generated work can pass expert review without disclosure. The immediate applications are in narrow, well-defined research domains with large hypothesis spaces. The 12-month risk: venues will start requiring AI disclosure in submissions, and the competitive landscape shifts to who builds the better agentic research pipeline, not just the better base model.

Nemotron 3 Super: 120B Hybrid Mamba-Attention MoE — 12B Active Parameters
NVIDIA Research · April 2026 · arXiv:2604.XXXXX

One-line finding: A 120B-parameter model with only 12B parameters active per forward pass, using a novel Mamba-Attention hybrid architecture instead of pure transformer, showing frontier-competitive quality at significantly lower inference cost.

Nemotron 3 Super combines two efficiency innovations: MoE routing (only 12B of 120B parameters active — covered in Issue #23) and Mamba blocks (a state space model that replaces some attention layers with a more memory-efficient recurrence). Pure attention scales quadratically with context length; Mamba scales linearly. For long-context tasks, this means 4–8x lower memory and compute at equivalent context lengths vs pure transformer MoE. Apache 2.0 licence.

Why it matters in 6 months: If the Mamba-Attention hybrid architecture proves stable across fine-tuning and deployment (the open question — hybrid architectures have historically been harder to train stably than pure transformers), this becomes the template for the next generation of open-weight models. The combination of MoE compute efficiency and Mamba context efficiency could enable 1M+ token models at Sonnet-level inference costs within 12 months. NVIDIA shipping this as open-weight signals their intent to seed the inference hardware ecosystem — run Nemotron, buy H100 time.
