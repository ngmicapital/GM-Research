Orthrus — dual autoregressive + diffusion architecture with shared KV cache ⚡

Research HuggingFace trending: 37 upvotes Architecture: AR + diffusion dual-stream Method: shared KV caches + consensus

New for Issue #53 per HuggingFace papers trending: Orthrus is a dual-architecture framework that combines autoregressive LLMs with diffusion models to achieve fast parallel token generation while maintaining exact inference fidelity through shared KV caches and consensus mechanisms. The structural innovation is the shared cache: rather than running AR and diffusion as separate decoding streams (which inflates memory and breaks consistency), Orthrus runs them on the same KV state with a consensus protocol that resolves token-level disagreements. The "exact inference fidelity" claim is the meaningful part — many AR-plus-X hybrids trade fidelity for parallelism; Orthrus claims both. Sits in the same architecture-of-2026 family as Gemma 4 MTP (Issue #51 carry), speculative decoding generally, and the SubQ subquadratic-attention thread (still unverified, §01).

⚡ Why it matters in 6 months: Orthrus sits at the structural intersection of two of this briefing's recurring threads — the architecture-of-2026 thesis (speculative decoding + linear attention as the cost-floor migration mechanism) and the production-tier inference scheduling work (MARLIN, Issue #52). If Orthrus-style dual-stream architectures with shared KV caches and consensus become the default decoding stack in 12–18 months, the inference cost-curve for frontier-tier models flattens further — which is structurally bullish for managed cloud + dedicated hardware (Cerebras, §05) and structurally bearish for marginal DePIN compute (§03 — AKT/RNDR/TAO). For the briefings-stack: no direct action; this is the kind of paper that becomes a Gemini 4 / Claude 5 / GPT-6 default architecture pattern 12–18 months out.

Code-as-Room — MLLM agentic framework, Blender code as execution harness

Research HuggingFace trending: 50 upvotes Domain: 3D indoor room generation Method: top-down image → Blender code

New for Issue #53 per HuggingFace trending: Code-as-Room is a novel MLLM-based agentic framework that generates 3D indoor rooms by converting top-down images into executable Blender code through a structured execution harness with cross-stage memory. The methodological novelty is the code-as-intermediate-representation pattern — rather than generating 3D meshes directly (which has been the canonical 3D-AI approach), Code-as-Room generates Blender Python code that produces the room when executed. Cross-stage memory means each generation stage retains context from prior stages, which prevents the "drift" pattern that pure-mesh-generation approaches suffer from. The 50-upvote HuggingFace trending position makes this the highest-engagement AI paper of the post-I/O week.

⚡ Why it matters in 6 months: Code-as-Room generalises beyond 3D generation. The pattern — generate executable code as an intermediate representation, execute, retain cross-stage memory — is exactly the workflow shape that the briefings-site's multi-agent stack already runs (skills generate code, code executes, output feeds the next stage). The 3D-rooms application is the demo; the generalisable architecture is the news. For dc's stack: not directly relevant today, but the code-as-intermediate-representation pattern is worth keeping in mind for any future visualisation pipeline (the visualisations.html generator could plausibly adopt a similar pattern for complex chart specifications). For the case-survey work: parallel applications in legal-document drafting (generate executable contract clauses + clause-level memory) are an interesting six-month thought experiment.
