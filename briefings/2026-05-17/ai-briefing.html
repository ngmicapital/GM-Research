§07 — Research Radar

Agentic AI Orchestration Should be Bayes-consistent (May 4, arXiv) ⚡

Research

The 30-author position paper argues that while making LLMs themselves Bayesian is computationally intensive and unnecessary, the orchestration layer — the system deciding which tools to call, how much resource to invest, when to escalate to a slower/more-expensive model — should be Bayes-consistent. The framing: an agentic system maintains "calibrated beliefs" over task-relevant latent quantities, which lets it allocate compute and tool calls in a principled way rather than via greedy heuristics. Result claims: fewer redundant tool calls, better resource allocation, more reliable termination.

⚡ Why it matters in 6 months: This is the kind of "obvious in hindsight" framing that propagates fast into agent frameworks. If the Microsoft Agent Framework or OpenAI Agents SDK ships a Bayesian routing layer in the next two quarters, this is the paper that licensed it. For the briefings-site stack, the practical implication is mostly upstream — if Claude Code adds Bayes-consistent skill selection in 2.1.150+, dispatched-agent reliability gets meaningfully better without any user-side work.

§08 — Technicals

Speculative decoding crossed from research into production this week — Google's Gemma 4 Multi-Token Prediction drafter (released May 5) delivers up to 3× faster inference with no output-quality degradation, and the broader MTP / speculative-decoding stack (vLLM, GitHub Copilot's 50% latency cut) is now the canonical answer for cost-efficient inference scaling.

Gemma 4 Multi-Token Prediction (MTP) — 3× speedup, lossless ⚡

Launch Research Released May 5 3× inference speedup Zero quality degradation (claimed)

Per Google AI for Developers blog / abit.ee / TheCodersBlog coverage: Google released the Gemma 4 MTP drafter on May 5, 2026. The technique — Multi-Token Prediction via speculative decoding — uses a small fast "drafter" model to predict several tokens ahead of a larger target model, then the target verifies all draft tokens in one parallel forward pass; agreed tokens are accepted, disagreed tokens are rejected and the target's own output replaces them. Headline result: up to 3× speedup in real-world workloads with no output-quality degradation. The architecture is now also integrated into vLLM's native MTP backend, removing the need for a separate draft model.

⚡ What could this enable in 3–6 months: Inference cost roughly tracks GPU-seconds; a 3× speedup with the same output is a 3× cost-reduction. That cascades. (a) The same model becomes 3× cheaper to serve, which moves the API-price curve down across the industry. (b) The same dollar buys 3× more inference, which moves agentic workloads (long-context, multi-step reasoning, tool-use loops) from "expensive" to "affordable." (c) Open-source models running on consumer GPUs become 3× more competitive against frontier API endpoints, pulling the local-fallback substitution decision (§01 / DeepSeek V4) closer for cost-sensitive workloads. Speculative decoding is now the canonical inference-efficiency pattern for 2026.

GitHub Copilot — 50% completion-latency reduction via speculative decoding

Update Workflow Median completion: 1.4s → 0.7s Speculative decoding + distillation

Per Premai / dasroot.net / vLLM docs coverage of the March 19 GitHub Copilot update: median completion latency cut from 1.4 seconds to 0.7 seconds using a draft model predicting tokens in parallel + model distillation. This is the production-tier proof-point that speculative decoding holds up at code-completion scale (i.e. millions of requests per day across enterprise customers, not just lab benchmarks). The caveat surfaced in dasroot.net's coding-vs-creative benchmark: speculative decoding helps coding workloads substantially (high token-agreement rate) but can slow creative tasks (low token-agreement rate, more rejection overhead).

⚡ What could this enable in 3–6 months: The two-tier prediction (Copilot: confirmed; Gemma 4: lossless 3×) sets the floor. Expect every frontier API to ship native MTP in 2026 — Anthropic's Sonnet 4.x / Opus 4.x and OpenAI's GPT-5.x families will quietly cut median latency 30–50% via this technique without re-versioning the model. The user-facing signal is "responses feel faster"; the unit-economics signal is "agentic workloads stop being prohibitive at scale." For dc's stack: agent-loop workflows that were borderline at $0.50/run become $0.15/run runs over the year.

🔬 Plain-English Explainer

Think of it like this. When an AI writes a sentence, it usually generates one word at a time — predict word 1, run the model, predict word 2, run the model, predict word 3. The biggest cost in this loop is the model run itself, not the prediction. So researchers built a trick called speculative decoding: a small fast "guesser" model predicts the next 4–5 words ahead, all at once, and then the big slow "checker" model verifies all 5 predictions in a single run. If the guesser got 4 out of 5 right, the AI just generated 4 words for the cost of one model run. The practical result is that the AI responds 3× faster while saying exactly the same thing. For traders, this matters because: (a) the cost per AI question drops by roughly two-thirds without changing the answer quality, (b) the AI-compute tokens that bet on this (RENDER, AKT, TAO) face a tougher unit-economics race against Nvidia data-centres that now produce 3× more output per GPU-hour, and (c) agentic workflows that were too expensive to run continuously suddenly aren't.
