[Fundamentals]

What an Agent Loop Is — And Why It Changes What Software Can Do

Every AI tool in this week's briefing — Claude Code Routines, Digits MCP, AI Scientist-v2, Hermes Agent — is built around the same underlying pattern: an agent loop. Understanding the loop is understanding why agentic AI is qualitatively different from chatbots, not just faster at the same thing.

A chatbot works in a single pass: you give it a prompt, it produces an output, the interaction ends. An agent loop adds a feedback layer. The agent generates an action (write some code, search the web, query a database), observes the result of that action (the code ran and produced an error, the search returned these results), and uses that observation to decide the next action — and so on, iterating until the task is complete or the agent decides it's stuck. The loop can run dozens or hundreds of iterations on a single task. Claude Code, when working through a complex multi-file bug, isn't generating one response — it's running an agent loop: read the file, form a hypothesis, edit the code, run the tests, observe the failure, revise the hypothesis, edit again, re-run. Each iteration is a cycle of the loop.

The architecture has three core components: a planner (which generates the next action based on the goal and current state), a tool executor (which runs the action — a web search, a code execution, a file edit — and returns the result), and a memory layer (which stores what's been done, what was observed, and what's still outstanding). In simple agents, the memory is just the conversation context window. In sophisticated agents like Hermes (Issue #24), the memory is external — a persistent store that survives across sessions and is structured for retrieval rather than just sequential reading.

The reason agent loops change what software can do: they turn AI from a tool that assists with a task into a system that executes a task, iterating toward a goal without requiring human input at each step. This is why Claude Code can autonomously write, test, debug, and commit a feature without you hovering over it — the loop runs the scientific method (hypothesize, test, observe, revise) automatically. It's also why agents fail in characteristic ways: when the observation layer is noisy (e.g., a flaky test that sometimes passes), the planner makes wrong inferences; when the goal is underspecified, the agent optimises for the wrong proxy; when the loop runs too long without a stopping condition, it drifts.

Why this matters for the AI landscape: The MCP protocol is best understood as infrastructure for agent loops — it standardises how the tool executor component retrieves data from external systems. Every new MCP server (Digits, Circle, N-able) is adding a new class of action that agent loops can take. The next frontier in agentic AI isn't better planners (Claude is already good at planning); it's richer, more reliable tool executors and better memory architectures that let agents run longer without forgetting context or accumulating errors.

[Launch]

AI Scientist-v2 — First AI-Generated Paper to Pass Peer Review (SakanaAI)

SakanaAI published The AI Scientist-v2 (arXiv: 2504.08066) this month — an end-to-end agentic system that formulates scientific hypotheses, designs and executes experiments, analyses data, and autonomously writes manuscripts. The v2 breakthrough over the original: it no longer requires human-authored code templates. It works from scratch across diverse ML domains.

The landmark result: three fully autonomous manuscripts were submitted to a peer-reviewed ICLR workshop. One passed peer review — exceeding the average human acceptance threshold in blind review. This is the first AI-generated paper to successfully navigate peer review at an academic venue. The paper was accepted on its own content merits, not via a disclosure exception or special track. The codebase is open on GitHub (SakanaAI/AI-Scientist-v2) and is deployable today.

The mechanism is a progressive agentic tree search — rather than generating a single research direction and committing to it, the system simultaneously explores multiple hypothesis branches, allocating more compute to the branches that show early experimental promise, and prunes the dead ends. An enhanced AI reviewer component (using a Vision-Language Model) iteratively refines figure quality and content. The result is a system that mimics the iterative nature of actual scientific research, not just scientific writing.

Worth following closely. The immediate practical implication isn't "AI replaces researchers" — it's "AI can now close the loop between hypothesis and publication autonomously." The commercial applications that follow from this in 12–18 months: drug discovery pipelines, materials science screening, and algorithmic trading strategy research (generating and back-testing novel approaches without human intervention at each step). The open-source availability means the architecture is available for domain-specific adaptation now.

[Regulatory]

EU AI Act — August 2 General-Purpose AI Compliance Deadline Approaching

The EU AI Act's August 2, 2026 deadline for General-Purpose AI (GPAI) model providers is now 102 days away. This is the compliance threshold that applies directly to Anthropic, OpenAI, Google, and Meta — any provider offering a general-purpose AI model in the EU market must have submitted technical documentation, safety evaluations, and an EU-compliant usage policy by this date. GPAI models with systemic risk (defined as models trained on more than 10^25 FLOPs) face additional requirements: adversarial testing results, incident reporting, and energy usage transparency.

All four major frontier labs have been engaging with EU authorities since the Act passed, but the August 2 deadline is when compliance moves from preparation to legal obligation. Enforcement is handled nationally (each member state designates a market surveillance authority) with penalties up to €35M or 3% of annual global turnover for GPAI non-compliance.

Monitor — expect compliance documentation releases from Anthropic and OpenAI in May–June (they typically publish before deadline to demonstrate good faith). Watch for any changes to EU-region API terms or capability restrictions in that window. Labs may restrict certain model capabilities in EU regions to satisfy risk tier classifications — which could affect European API users on frontier tiers.

Transformer Forecast Collapse: MSE Loss as a Hard Ceiling for Financial Time Series (arXiv:2604.00064)
Andreoletti, 2026 · arXiv:2604.00064 · Submitted April 2026

One-line finding: For financial time series with low signal-to-noise ratios, increasing transformer model expressivity — more parameters, more layers — predictably increases forecast error rather than decreasing it, due to the mathematical properties of MSE loss on noisy data.

The argument: MSE penalises the model for not fitting the noise in the training data, so more expressive models overfit the noise more precisely. On test data with independent noise, the result is an error floor of twice the irreducible minimum — regardless of model size or training duration. This is a formal proof, not an empirical claim — the ceiling is mathematical, not a tuning problem.

Why it matters in 6 months: This paper provides theoretical grounding for why AI-based crypto price prediction models underperform — and points to where the real leverage is: loss function selection (alternatives to MSE) and ensemble approaches that explicitly model noise rather than trying to fit through it. For anyone using or building AI-assisted market analysis tools, the implication is blunt: bigger models won't solve the forecasting problem; the architecture choices around loss functions will. Directly relevant context for evaluating any "AI trading signal" tool that uses neural networks for price prediction.
