§01 Model Landscape

Model Landscape

No new frontier model dropped this weekend — the dominant model story is OpenAI killing Sora as it consolidates around the GPT-5.5 / Codex productivity stack.

OpenAI shuts down Sora — web/app discontinued April 26, API September 24

[Update] OpenAI Video gen exit ⚡ delta from #30

OpenAI's Sora web and mobile experiences were officially discontinued yesterday, April 26, executing on the March 24 announcement. The API is scheduled to follow on September 24, 2026. OpenAI has cited high compute costs, declining user engagement (reportedly down from 1M to under 500K MAU), unresolved copyright exposure, and a strategic refocus on enterprise/productivity tools. The collateral damage is the December 2025 Disney partnership — a reported $1B integration of 200+ Disney/Marvel/Pixar/Star Wars characters — which has been cancelled. Disney was reportedly given less than an hour's notice before the public announcement.

The Sora user-data export window (sora.chatgpt.com/exports/me) is now the only path to recover content; all account data will be permanently deleted post-cutoff.

⚡ Implication: OpenAI is now visibly choosing to compete on agents and code (GPT-5.5, Codex 0.125, Workspace Agents) rather than on consumer-grade generative video — the Sora 2 product was burning compute at scale without finding a sustainable user base. The competitive landscape for video gen now belongs to Google Veo 3, Runway Gen-4, and Kling 2.5. For dc: not directly action-relevant, but if any briefing pipeline ever embedded Sora calls, audit them — the API has 5 months left.

Public-API leaderboard — five frontier launches in nine days, density now matters more than headlines

[Benchmark] Multi-lab

Stepping back: the April 16–24 release run — Opus 4.7 (Apr 16, SWE-Bench Verified 87.6%), Kimi K2.6 (Apr 20, AA Intelligence Index 54), Qwen 3.6-27B (Apr 22), GPT-5.5 (Apr 23, SWE-Bench Verified 88.7%), DeepSeek V4 Pro/Flash (Apr 24, 1M context, $1.74/$0.14 per M input) — produced more frontier-quality model launches in nine days than any comparable window since GPT-4. Good-enough inference pricing has dropped roughly 50% versus January 2026.

⚡ Implication: The "which model is best" question now has no single answer at the frontier — the gap between Opus 4.7, GPT-5.5, Gemini 3.1 Ultra, and the Kimi/DeepSeek open-weights cohort is small enough that workflow fit (Claude Code, Codex, Cursor) determines the winner more than benchmark scores. Stay on Opus 4.7 for coding/research/agents; treat the others as on-call alternatives, not replacements.
§02 Claude Ecosystem

Claude Ecosystem

Anthropic's compute supply through 2030 is now fully wired — Google's $40B / 5 GW commitment lands four days after Amazon's $25B and confirms the next two model generations have unlimited runway.

Google commits up to $40B to Anthropic at $350B valuation — $10B cash now + 5 GW compute

[Funding] Google Cloud TPU 8

Bloomberg, CNBC and Reuters confirmed Friday that Alphabet will invest up to $40 billion in Anthropic — an initial $10B in cash now at a $350B valuation (matching the February Series G mark) and up to $30B more conditional on performance milestones. Beyond cash, Google Cloud will supply 5 gigawatts of dedicated compute over five years starting in 2027, with options to expand. This brings cumulative Google investment in Anthropic to ~$43B (vs ~$3B prior position and a 14% pre-deal stake), and stacks on top of Amazon's $25B announced four days earlier (§05 in Issue #30) and the $30B Series G at $380B post-money closed February 12.

Anthropic's annualised revenue run-rate crossed $30B in March/April 2026, up from $9B at end-2025 — a ~233% intra-quarter expansion that flipped the OpenAI/Anthropic revenue ranking for the first time. Enterprise customers spending $1M+ per year doubled from 500 to 1,000 in the eight weeks since the Series G.

⚡ Implication for dc: Two compounding signals. (1) Compute supply for Opus 4.8 / Sonnet 5 / Haiku 5 is now structurally over-provisioned across Trainium2/3 (Amazon) and TPU 8 (Google) — tearing the "but what if Anthropic gets compute-starved?" risk off the page through 2027–2028. (2) The $350B valuation gap between Google's strike price and the secondary-market $800B–$1T whisper number tells you Anthropic raised on terms that protect the cap table while accepting the strategic compute. dc's rational stance: keep Opus 4.7 as the daily driver and don't try to predict the pricing path — the runway is already paid for.

⚡ Implication: If any briefing or research workflow ever needs reproducible Python execution (charts, ticker analysis, data validation), the Colab MCP server is now a viable replacement for local Python tools. §06 Workflow & Tools

Workflow & Tools

The most useful workflow shift this week is also the quietest: OAuth 2.1 incremental scope consent in the MCP spec — granular tool authorisation finally exists, and the long-running "all-or-nothing access" complaint is dead.

MCP spec — OAuth 2.1 with incremental scope consent now standard

[Workflow] MCP Auth

The MCP specification this month formally adopted OAuth 2.1 with incremental scope consent. Practically, this means an MCP client (Claude Code, Cowork, Goose, etc.) can ask for narrow permissions when first connecting and request additional scopes only when a specific tool needs them — the user gets a per-tool prompt rather than a blanket "this server can do everything" approval. The spec change cascades into every server SDK update over the next few weeks.

⚡ Implication: The blocking complaint about MCP from security-conscious users ("I can't approve a write-tool without also approving every read-tool") is now resolved at the protocol level. For dc: not action-required today, but the next time you connect a new MCP server (Notion, Gong, BigQuery, etc.), you'll get more granular prompts — accept this as an improvement, not a friction.

Codex 0.125 ships — Unix socket transport, persistent permission profiles

[Update] OpenAI Codex

OpenAI shipped Codex 0.125 (Apr 24) alongside the GPT-5.5 rollout. Notable bits: app-server integrations now support Unix socket transport, permission profiles persist across sessions and MCP sandbox states, and rollout tracing now records tool relationships and multi-agent workflows. This is Codex closing structural gaps with Claude Code (persistent settings landed in Claude Code 2.1.119 the same day) — not a leap, but a normal-versioned tightening of the loop.

⚡ Implication: dc's stack runs Claude Code, not Codex, so the direct effect is zero — but the practical signal is that the Codex/Claude Code parity gap is narrowing on infrastructure, not just on model strength. If you ever evaluate a swap (you shouldn't unless workflow-specific friction emerges), this is the version of Codex worth benchmarking against.
Try this week: the Rate Limits API from §02. Hit the new endpoint at the start of any long-running scheduled task (briefings, ticker, health-check) — if your remaining budget is under, say, 30%, exit early with a Telegram notification rather than letting the task fail mid-run. ~10 minutes to wire, removes a class of late-night failure modes.
§07 Research Radar

Research Radar

The most practically important paper this week is the Cambridge hafnium-oxide memristor result — a credible 70% energy reduction path for inference if it scales out of the lab.

Cambridge hafnium-oxide memristor — 70% energy reduction for AI inference

[Research] Hardware Cambridge

University of Cambridge researchers published a nanoelectronic memristor device using a modified hafnium oxide stack that mimics how biological neurons process and store information at the same time. Headline number: a credible path to ~70% energy reduction for inference on the same workload class versus standard CMOS. Memristors aren't new — the novelty is stability and low-energy switching at near-room-temperature, the two things that have historically blocked the architecture from leaving the lab.

⚡ Why it matters in 6 months: If this scales, the next decade of "compute-in-memory" hardware (where computation happens in the memory cell instead of moving data between memory and processor) gets real. That's the architectural shift that takes inference cost from "expensive but worth it" to "ambient/free for most use cases" — and it changes the economics of AI-token DePIN networks (RENDER, AKT) faster than people expect. Not action-relevant today, but a 6–18-month watch item, especially for any conference where AMD, Intel, or Samsung announces a memristor chip.

MemPalace — open-source long-term memory for LLMs using the method of loci

[Research] Memory systems

MemPalace launched this month as an open-source AI memory system that applies the ancient method of loci (memory palace technique) to organise long-term memory for LLMs. Concretely: instead of a flat embedding store, memories are arranged in a synthesised spatial layout that the model traverses to retrieve. Early benchmarks claim better recall on multi-hop queries than standard RAG, with much smaller index sizes. Code is on GitHub.

⚡ Why it matters in 6 months: Most "AI memory" systems today are RAG with extra steps. If MemPalace's spatial-organisation approach holds up under scrutiny, it's the kind of structural insight that gets adopted into products like Anthropic's Memory Beta or ChatGPT Memory within a quarter. For dc: not a tool to adopt, but a useful prior — when evaluating any "AI assistant with memory" product, ask how it organises information, not just how it stores it.
§08 Technicals

Technicals

Inference silicon is fragmenting fast — Google TPU 8/8i, Intel-SambaNova SN50 RDU, and the disaggregated serving pattern are all attacking the same Nvidia bottleneck from different angles.

Google TPU 8 / 8i — training and inference split, 384MB SRAM per chip

[Update] Google Hardware

Google announced the eighth-generation TPU family (Apr 22) — and for the first time split training and inference into distinct chips. The training TPU runs at 2.8× the performance of the seventh-gen Ironwood TPU at the same price; the inference variant (TPU 8i) is 80% faster than Ironwood for inference workloads. The architectural shift is the inference chip moving to SRAM-on-die (384 MB per chip — triple the Ironwood) rather than HBM-bandwidth-limited DRAM, which is the same architectural choice Cerebras uses on its WSE-3 wafer-scale chip. Both ship later in 2026, with Gemini 3.1 inference confirmed as the first production workload.

Intel-SambaNova SN50 RDU — heterogeneous inference for agentic workloads

[Update] Intel SambaNova

Intel and SambaNova announced a joint reference architecture combining Xeon CPUs, GPUs, and SambaNova's SN50 RDU (Reconfigurable Dataflow Unit) for agentic inference workloads. The SN50 sits at the decoding stage and is designed specifically to address memory-bandwidth bottlenecks on long-context inference — the same bottleneck Cerebras and Google's TPU 8i attack with on-die SRAM. The disaggregated-serving pattern (separate prefill and decode hardware clusters) is now the consensus design, with vLLM, SGLang, and TensorRT-LLM all maturing implementations claiming up to 6.4× throughput and 20× latency variance reduction versus monolithic serving.

Inference market on track for $50B+ in 2026

[Update] Market

Specialised inference silicon is now a $50B+ market in 2026 per Lukas Brunner's tracking — and growing faster than the overall AI hardware market. The structural reason: training is a one-shot capex spend, but every inference query is permanent recurring opex, so as deployment scales, inference economics dominate the bill. Cerebras IPO mid-May, Groq's expected follow-on, and TPU 8i public availability all sit inside this expansion.

🔬 Plain-English Explainer

For most of the AI boom so far, training a model — teaching it from scratch — has been the expensive part. That's changing fast, because once a model exists, every single time anyone uses it (every prompt, every API call) costs money to run. Multiply that by billions of users and it dwarfs the one-time training bill. So the chip industry is now racing to build hardware specifically optimised for "running" trained models cheaply, rather than for "training" them.

Three different solutions arrived this week. Google's TPU 8i puts a lot of fast on-chip memory (SRAM) right next to the compute, so the chip doesn't waste time fetching data from slower memory. Intel and SambaNova built a chip that handles only the slow "thinking out loud" stage of a model's response, leaving other stages to GPUs. And the whole industry is converging on a pattern called "disaggregated serving" — basically, splitting the work across different specialised chips instead of using one chip for everything.

For traders: this is what's actually unlocking the AI-token sector right now. The "decentralised compute" thesis (TAO, RENDER, AKT) only works if compute is scarce and orchestrating it across many providers is valuable. As compute gets cheaper from the Google/Cerebras/Intel side, the DePIN networks have to compete on different ground — orchestration quality, geographic coverage, and quality-of-service guarantees rather than raw price. Stay long the utility tokens with real revenue (RENDER's $38M/month, AKT's burn-mint compute economics) and short the pure-narrative basket.

⚡ Implication in 3–6 months: Three converging inference innovations means cloud-API pricing has another leg of compression coming. Watch Anthropic's Sonnet/Haiku tiers — those are the ones most exposed to a price cut, since Opus is positioned as the premium reasoning tier and competes less on cost. Realistically expect the Haiku 4.5 / Sonnet 4.6 input-token price to come down 20–30% by Q3 if Cerebras prices well at IPO and TPU 8i lands on schedule.
