Claude Ecosystem

Anthropic updates, Claude Code & MCP ecosystem
Claude Code's late-April batch adds session recall and 1-hour prompt caching — the two features that most directly reduce cold-start pain on large, long-running agent sessions.
[Update] [Workflow]
Claude Code Late April Features — /recap, 1-Hour Caching, Custom Themes, MCP Hooks
/recap command ENABLE_PROMPT_CACHING_1H Custom themes MCP tool hooks Confirmed: releasebot.io + GitHub releases

Following the quality regression fixes in Issue #28, Claude Code has continued its rapid release cadence with several power-user features:

/recap — a session context summary that fires when returning to a paused session. Configurable in /config; manually invocable at any point. Directly addresses the "I forgot where I was" cost of multi-day agent workflows.

ENABLE_PROMPT_CACHING_1H env var — opts into 1-hour prompt cache TTL on API key, Bedrock, Vertex, and Foundry. FORCE_PROMPT_CACHING_5M forces 5-minute TTL for tighter control. For sessions with large shared context (system prompts, codebase context), this is a meaningful cost reduction.

Custom themes via /theme — create and switch between named themes, or hand-edit JSON in ~/.claude/themes/. Plugins can ship themes via a themes/ directory.

Hooks → MCP tools — hooks can now invoke MCP tools directly via type: "mcp_tool". Combined with built-in slash commands (/init, /review, /security-review) now being discoverable by the model via the Skill tool, this completes the MCP-native agent loop.

⚡ Implication for dc: If you use /resume on sessions longer than a few hours, /recap is the most directly useful addition. Upgrade now: npm update -g @anthropic-ai/claude-code. The 1-hour caching env var will reduce costs on any session where the same large context block repeats — worth setting permanently on your primary API key config.

Open-Source Pulse

GitHub trending, HuggingFace releases & community projects
Karpathy's skills repository triggered a full ecosystem explosion — self-evolving agents are converging on a common "skills as composable units" architecture that every major open-source agent framework is now adopting.
[Open Source] [Workflow]
andrej-karpathy/skills — +44K Stars · Week of April 22
+44K new stars #1 GitHub Trending Confirmed: shareuhack.com GitHub weekly + Medium

Andrej Karpathy's skills repository topped GitHub Trending for the week of April 22 with +44K new stars, triggering what observers are calling a "skills ecosystem explosion." The core idea: skills are reusable, composable knowledge units that agents can discover, execute, and chain — analogous to functions in a programming language, but for agent behaviours.

Within 72 hours of the repo going viral, multiple derivative frameworks appeared: GenericAgent (see below), SkillForge, and several LangChain and DSPy-native ports. The pattern is now clearly the dominant architecture for self-improving agent systems in April 2026.

⚡ Implication: Skills-based agent architecture is becoming the default, not a research curiosity. If you're building Claude-based agents, understanding the skills pattern now (before it's abstracted away by frameworks) gives you a meaningful design advantage. Karpathy's repo is readable in an afternoon — worth doing.
[Open Source] [Launch]
GenericAgent — Self-Building Skill Tree, 6× Token Efficiency
3,300 lines seed code 6× fewer tokens vs baseline Confirmed: shareuhack.com + Medium trending

GenericAgent makes a specific technical claim: starting from 3,300 lines of seed code, the agent builds its own skill tree, achieves full system control, and consumes 6× fewer tokens than baselines on equivalent tasks via skill reuse. The efficiency gain comes from not re-inferring behaviour that has already been distilled into a skill — essentially a memoisation layer over the agent's learned capabilities.

Architecture differs from Hermes Agent (Issue #27–28) in one key way: GenericAgent's skills are explicitly typed with input/output schemas, making them composable without ambiguity. Hermes uses a more fluid, memory-based approach. The typed approach is easier to audit and debug.

⚡ Implication: The 6× token efficiency claim is worth verifying on your own tasks before committing to the architecture — but if it holds even partially, skill-reuse is the most practical cost-reduction lever available for long-running agents. Start with a controlled eval: one recurring task, same model, skills vs. no skills, compare token counts.

Technicals

Architecture breakthroughs, inference optimisation & hardware advances
DeepSeek's Hybrid Attention Architecture and Skymizer's HTX301 chip both attack the same problem from opposite ends — making 1M+ token inference cheap enough to run at production scale.
[Launch] [Benchmark]
Skymizer HTX301 / HyperThought Platform — 700B-Parameter Inference on a Single PCIe Card
6 × HTX301 chips 384 GB memory per card ~240W per card LISA™ ISA Confirmed: Yahoo Finance + Manila Times (April 23)

Skymizer Taiwan previewed its HTX301 inference chip integrated with the HyperThought software/hardware co-design platform. A single PCIe card with 6 HTX301 chips and 384 GB of unified memory can now run 700B-parameter model inference at approximately 240W — enabling enterprise-grade local AI without rack-scale infrastructure.

The key architectural innovation is prefill/decode disaggregation: LLM inference has two fundamentally different compute phases. Prefill (reading the input prompt) is compute-bound; decode (generating output tokens) is memory-bandwidth-bound. GPU-centric hardware forces both onto the same silicon, creating under-utilisation. HTX301 + HyperThought separates these phases explicitly, using LISA™ (Language Instruction Set Architecture) — a custom ISA optimised for transformer workloads rather than generic matrix multiplication.

⚡ Implication: If the 700B inference-per-card figure holds in third-party benchmarks, Skymizer's approach could accelerate the timeline for on-premise frontier-model deployment by 18–24 months versus a Nvidia-only trajectory. Watch for independent validation — the announced figures are from the company's own preview materials.
[Launch] [Benchmark] [Open Source]
DeepSeek Hybrid Attention Architecture (HAA) — 1M Token Context Without Proportional Memory Scaling
MLA + sparse attention hybrid 1M token context window Open-sourced in V4-Flash weights Confirmed: DeepSeek API Docs + VentureBeat + HuggingFace model card

DeepSeek V4's Hybrid Attention Architecture (HAA) combines Multi-head Latent Attention (MLA) variants with sparse attention patterns designed to maintain long-conversation coherence without the quadratic memory growth that normally makes 1M-token context impractical. The architecture is open-sourced in the V4-Flash HuggingFace release, making it immediately accessible to researchers and fine-tuners.

The practical claim: HAA enables a model to "remember queries across long conversations" — meaning attention across the full million-token context remains computationally feasible at inference time, not just at training time. If this holds in practice, it removes a key limitation in agentic workflows where context accumulates across many tool calls.

⚡ Implication: Open-sourcing HAA matters more than the model release itself. Within 3–6 months, expect HAA-based fine-tunes from the HuggingFace community to appear with domain-specific capabilities (code, legal, medical) at the same 1M-context scale. The competitive moat for closed-source long-context models narrows further.
🔬 Plain-English Explainer — What Does This Actually Mean?

Think of running a large AI model like a factory with two very different workstations. The first station (prefill) reads your entire question at once — it's like a production floor running at full speed, compute-intensive. The second station (decode) writes your answer one word at a time — it doesn't need raw speed, it needs to rapidly move data between memory and the processor. The problem: most AI chips today cram both workstations onto the same hardware, which means one is always sitting idle while the other runs.

Skymizer's HTX301 chip is designed to keep both workstations busy at the same time — a technique called prefill/decode disaggregation. The practical result: a 700-billion-parameter model can now fit on a single card that plugs into a normal server, running on roughly the power of a high-end gaming PC. That's the equivalent of running a full GPT-4-class model on equipment that fits in a small rack rather than an entire data centre.

DeepSeek's HAA is tackling the same problem from the software side: instead of paying for all the memory needed to "look back" across 1 million tokens at every generation step, it uses clever mathematical shortcuts to maintain the same effective memory without the proportional cost. Think of it like a well-indexed book where the AI doesn't need to re-read every page to remember what was said on page 3 — it has a smart index system.

For traders: these advances mean frontier AI compute is moving toward enterprise-local infrastructure, cutting cloud dependency and long-term inference costs. Infrastructure plays (Render, Akash, Gensyn) benefit from any world where cheap compute is the new moat — and cheap compute is exactly what both announcements this week accelerate.

⚡ Implication in 3–6 months: Prefill/decode disaggregation and open-source long-context architectures converge into a world where 1M-token inference on local hardware is a commodity. Closed-source model providers lose the context-length moat. Application layer — what you do with the context — is the only remaining differentiation.
