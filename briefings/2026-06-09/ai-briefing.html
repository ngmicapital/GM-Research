§02 Claude Ecosystem

June 15 is the most operationally important date on Anthropic's calendar this month: Sonnet 4 and Opus 4 API endpoints retire, Agent SDK billing splits into a separate credit bucket, and the migration window is now six days — not six weeks.

June 15 deprecation — six days left ⚡

update
After June 15, API requests to claude-sonnet-4-20250514 and claude-opus-4-20250514 return errors. Migration path: swap to claude-sonnet-4-6 (or claude-sonnet-4-5) for general workloads; swap to claude-opus-4-8 for complex/agentic pipelines. The model-string change is a one-liner in most codebases — the risk is teams that have not audited every endpoint. Consumer Claude.ai accounts and Claude Code interactive sessions are unaffected.

Anthropic notes that prompting styles, tool-use conventions, and JSON response formats are stable across 4.x generations. No prompt rewrites required for moving from 4.0 to 4.6 or 4.8. The main gotcha is hardcoded versioned identifiers in CI, integration tests, and legacy API wrappers.

Agent SDK billing split — separate credit pools from June 15 ⚡

update

Starting June 15, claude -p, Claude Code GitHub Actions, Agent SDK calls, and third-party apps authenticating through the SDK will draw from a new monthly credit bucket: $20 for Pro, $100 for Max 5×, $200 for Max 20×. Credits reset at billing cycle start; unused credits do not roll over. Once the credit is exhausted, additional Agent SDK usage flows to pay-as-you-go usage credits (if enabled) — or stops entirely if usage credits are off.

What this means for power users

A Max 5× user running heavy Claude Code GitHub Actions workflows now has $100/month of "free" agent calls, then pays API rates. At current Opus 4.8 pricing, $100 buys roughly 1.4M input tokens or ~3.3M output tokens of agent work per month. Teams running multi-step agentic pipelines should model their June usage now — not on July 1 when the bill lands.

Claude Code — latest harness improvements ⚡

workflow

The most recent Claude Code harness drops add: fallback model chaining (up to 3 fallbacks when primary is overloaded), glob pattern deny rules (wildcard * blocks all tools in a category), and hardened cross-session messaging (messages relayed from other Claude sessions no longer carry user authority — a meaningful security tightening for multi-agent setups). MCP sub-1000ms timeout values now correctly fall back to MCP_TOOL_TIMEOUT rather than silently aborting every call.

Claude Managed Agents — private MCP + sandboxed execution ⚡

launch

Claude Managed Agents now support sandboxed execution environments you control, connectable to private MCP servers. The execution boundary and the service mesh both run within enterprise perimeter — a significant enterprise security upgrade that mirrors what Google shipped for Gemini. Combined with the Agent SDK billing split, this positions Anthropic's agentic stack as a production-grade enterprise offering rather than a developer preview.

§07 Research Radar

This week's research consensus: agent reliability is now primarily a harness problem, not a model problem — and the empirical evidence from three independent papers converges on the same structural finding.

Towards a Science of AI Agent Reliability (arXiv 2602.16666)

research

Updated June 2, 2026. Rabanser et al. evaluate 15 models across two complementary benchmarks and find that recent capability gains (the Opus 4.7→4.8 jump, GPT-5→5.5) have yielded only small improvements in reliability. The core finding: capability and reliability decouple above a threshold — once a model can do a task, whether it does it consistently is a function of the system wrapped around it, not the model itself. This is the empirical grounding for the broader "harness-not-model" narrative that dominated practitioner discourse in May.

From Model Scaling to System Scaling: Scaling the Harness in Agentic AI (arXiv 2605.26112)

research

Once models reach a sufficient capability threshold, gains in long-horizon agent performance increasingly depend on how the system around the model is designed — not the model's raw capability. The paper introduces a framework for "harness scaling": structured execution layers that provide retry logic, tool fallback, state management, and error recovery. The finding maps directly onto Claude Code's recent releases (fallback model chaining, hardened cross-session security) — Anthropic appears to be building the harness paper's recommendations into production tooling in real time.

International AI Safety Report 2026 (arXiv 2602.21012)

research

The 2026 International AI Safety Report — mandated by Bletchley Summit nations and written by 100+ experts — synthesises current evidence on frontier AI capabilities, emerging risks, and safety mechanisms. Key signals: (1) capability-safety gaps are widening as agentic deployment outpaces alignment research; (2) multi-agent systems create new attack surfaces not captured in single-agent safety evaluations; (3) the report's risk taxonomy explicitly identifies tool-augmented agents as a distinct risk class — relevant context for the "harness reliability" papers above. The report feeds directly into EU AI Act implementation guidance for high-risk systems.
