Try this today: alwaysLoad: true for high-frequency MCP servers

WorkflowClaude Codev2.1.121

The alwaysLoad: true field on MCP server config (new in 2.1.121) tells Claude Code to skip tool-search deferral for that server — every tool is loaded into the active toolset on session start. The cost is context (a small block of schema) for every session; the benefit is no round-trip the first time you call a tool. Right call for: Telegram (every message), scheduled-tasks (every scheduled run), Notion if you're frequently fetching pages. Wrong call for: bulky servers you call rarely (BiGquery, Gong) — keep those deferred.

⚡ Implication: Five-minute change in ~/.claude/.mcp.json with measurable latency benefit on the highest-frequency surfaces. The simplest rule: if you call a server in >30% of sessions, set alwaysLoad: true; otherwise keep it deferred.

Research Radar

"Less Is More: Cognitive Load and the Single-Prompt Ceiling in LLM Mathematical Reasoning" reframes the multi-shot vs single-shot trade-off — and it's a result that affects how briefing prompts should be structured.

Cazares (2026) — Cognitive Load and the Single-Prompt Ceiling in LLM Math Reasoning

ResearcharXiv 2604.18897Prompt engineering

Author: Manuel Israel Cazares. One-line finding: formal mathematical reasoning has a hard ceiling on single-prompt complexity — past a certain density of constraints in one prompt, performance collapses non-linearly even on models that solve the components individually. Decomposing into 3–5 sequential prompts beats stuffing the same logic into one prompt by a wide margin. Why it matters in 6 months: the result generalises beyond math. Any agentic loop that pushes too many constraints into a single inference call (briefing skills with twelve "must do X" rules, code-review prompts trying to enforce six review categories at once) is hitting an analogous cognitive-load ceiling. The fix is structural: split the prompt, not enlarge the model.

⚡ Implication: Direct application to the briefings system. The AI/legal/biohacker SKILL files have grown to 200–400 lines and are likely operating at or above the cognitive-load ceiling. Worth a one-pass refactor: split each SKILL into a "data-fetch" prompt and a "draft-from-data" prompt rather than a single mega-prompt. Estimate: 10–15% quality lift on adherence to the brand-voice and no-repeat rules with no model upgrade needed.

Anthropic / academic collaborators — LLM agents reproduce social-science results from methods alone

ResearchReproducibility

arXiv 2604.21965v1. Tests whether LLM agents can replicate published social-science findings using only the methods section + dataset (no full-paper access). Result: agents recover the headline findings on roughly ~70% of replication targets, with the failure modes concentrated in studies that depend on tacit researcher choices not documented in methods. Implication for the broader field: methods-only reproducibility is now a measurable LLM benchmark, and "the methods are sufficient" is empirically testable, not a debate.

⚡ Implication: Monitor only — but worth filing for the legal-academic work with Jason Allen (SMU). Stablecoin/monetary-theory papers are heavy on methods sections; this technique will plausibly become a peer-review tool within 12 months. No action this week.

🔬 Plain-English Explainer — why "single-prompt ceiling" matters as much as the chip news

Here's the surprising research result: even when an AI model can solve each piece of a hard math problem on its own, asking it to solve the whole problem in one go can break it. Not because the model isn't smart enough — because the prompt is asking it to hold too many things in working memory at once. Think of it like trying to bake a cake while also being told the recipe, the timer rules, the oven settings, and the icing instructions all at the same time, in one breath. The fix isn't a bigger oven (a more capable model); it's breaking the instructions into stages. For traders, this matters because the most valuable AI workflows for the next 12 months won't come from frontier-model upgrades — they'll come from prompt architecture. The teams that figure out how to chunk their workflows correctly will get 10–20% quality gains for free, no GPU upgrade required. It's the software-side complement to the hardware story (TPU 8i, HAA): cheaper inference plus smarter chunking is where the real productivity multiplier lives, not in any single model release.
