GPT-5.6 Sol, Terra, Luna — Three-tier family, limited API access

OpenAI previewed the GPT-5.6 family on June 26. Three tiers: Sol (flagship), Terra (balanced, ~2× cheaper than GPT-5.5), and Luna (cheapest, still strong). Sol adds a Sol Ultra mode that routes work through sub-agents for the hardest problems. Initial rollout is API + Codex for a select group of partners, with broader GA in coming weeks.

On TerminalBench 2.1: Sol Ultra 91.9% → Sol 88.8% → Claude Mythos 5 88.0% → Luna 82.5% → Claude Opus 4.8 78.9%. Terra matches Claude Fable 5 at 84.3% and edges GPT-5.5 at 83.4%. The ranking is unambiguous on agentic terminal tasks: Sol Ultra is the new ceiling, and Terra is the cost-rationalization play for every team still on GPT-5.5.

US government export-control directives that hit Anthropic's Fable 5 on June 12 appear to apply to GPT-5.6 as well — broad preview access is conditioned on government clearance. Watch whether the same graduated unlock process (100 orgs first, then GA) plays out here as it did for Fable 5.

Claude Code — Dynamic Workflows GA

Anthropic shipped Dynamic Workflows as generally available in Claude Code CLI, Desktop, VS Code extension, Amazon Bedrock, Vertex AI, and Microsoft Foundry — all paid plans. The key spec: up to 1,000 agents per run, 16 concurrent, script held outside the context window so intermediate results don't bloat your session. The bundled /deep-research command is the fastest entry point — it fans out web searches, cross-checks sources by majority vote, and returns a cited report. Trigger with the keyword ultracode in any prompt to have Claude write and run a workflow for that task. Effort mode /effort ultracode makes every substantive task in the session a workflow automatically.

The architectural shift matters: with dynamic workflows, Claude writes the orchestration script and the runtime holds the plan — subagents stop being turn-by-turn and become script-bound workers. The script is rerunnable and saveable as a personal slash command. This is closer to a CI/CD job definition than a chat session.

Workflow & Tools

Claude Code Dynamic Workflows are the lead tool story this week — ultracode mode, /deep-research built-in, 16-concurrent 1,000-agent cap, resumable runs.

Claude Code Dynamic Workflows — operational details

Requires Claude Code v2.1.154+. Key operational facts from the docs:

  • Trigger: include ultracode in any prompt, or say "use a workflow" — Claude writes a JS orchestration script and hands it to the runtime
  • Scale: 16 concurrent agents, 1,000 agents total per run
  • Persistence: intermediate results stay in script variables, not the context window — runs are resumable within the same session; paused agents return cached results on resume
  • Built-in: /deep-research <question> — fans out web searches, cross-checks via voting, returns a cited report
  • Effort mode: /effort ultracode = xhigh reasoning + automatic workflow for every substantive task; resets on new session
  • Cost note: a single run can consume meaningfully more tokens than conversation-mode; start on a small slice (one directory, narrow question) to gauge spend
  • Save: press s in /workflows view to save any run's script as a personal or project slash command
The key architectural point: workflows move the orchestration plan into code (a rerunnable JS script), not into Claude's context turn-by-turn. This makes the orchestration inspectable, diffable, and schedulable — closer to a CI job than a conversation. The adversarial-review pattern (independent agents challenge each other's findings before reporting) is the quality mechanism that makes this better than just spawning more subagents.

Research Radar

MEM1 is the memory architecture paper to benchmark new agent stacks against; Deep Research Agents gives the first systematic taxonomy of planning strategies across commercial DR systems.

MEM1: Learning to Synergize Memory and Reasoning for Efficient Long-Horizon Agents (arXiv 2506.15841)

From Zijian Zhou et al. — an end-to-end reinforcement learning framework that trains language agents to maintain constant memory across extended multi-turn interactions. The problem it solves: standard agents append every prior turn to context regardless of relevance — memory grows without bound. MEM1 instead trains the model to consolidate prior state into a compact shared representation, discarding irrelevant information at each step. Results: MEM1-7B achieves 3.5× performance improvement while using 3.7× less memory versus Qwen2.5-14B-Instruct on 16-objective multi-hop QA. It also generalizes beyond its training horizon.

Why it matters: as dynamic-workflow and multi-agent systems scale to 1,000-agent runs, unbounded context growth is the primary cost driver. MEM1's approach — reasoning-driven memory consolidation via RL — is the architecture to benchmark against for production long-horizon agents.

Deep Research Agents: A Systematic Examination and Roadmap (arXiv 2506.18096)

A comprehensive survey and taxonomy of Deep Research (DR) agents — autonomous AI systems that perform multi-turn informational research via dynamic planning, multi-hop retrieval, iterative tool use, and structured report generation. The paper identifies three documented planning strategies: Planning-Only (Grok DeepSearch, H2O, Manus — fastest but most likely to pursue wrong decomposition), Intent-to-Planning (OpenAI Deep Research — asks clarifying questions before committing), and Unified Intent-Planning (Gemini Deep Research — surfaces the full plan for user review before execution). Also covers API-vs-browser retrieval strategies and MCP integration for ecosystem extensibility.

Why it matters: the Claude Code /deep-research workflow shipped this week is a practical instance of this architecture. Understanding which planning strategy a system uses tells you when to front-load clarification versus just letting it run.
