§01 — Model Landscape

GLM-5.2 — the open-weight model that costs less and codes better than GPT-5.5 ⚡

Launch Benchmark

Z.AI released GLM-5.2 on 16 June 2026 — a 753-billion parameter open-weights model under MIT license that beats GPT-5.5 on multiple long-horizon coding benchmarks and is available on Hugging Face, the Z.ai API, and 20+ third-party coding environments. The headline numbers: GLM-5.2 trails Claude Opus 4.8 by only 1% on FrontierSWE (the multi-hour autonomous engineering benchmark), while beating GPT-5.5 on the same test. It also carries a 1 million-token context window — a 5x jump from its predecessor GLM-5.1's 200k cap. Enterprise pricing starts at $12.60/month.

Gemini CLI retired — Antigravity CLI replaces it ⚡

Update

Google retired Gemini CLI on 18 June 2026 and migrated users to Antigravity CLI — the developer-facing shell that wraps Google's Managed Agents platform. The transition is more than a rename: Antigravity spins up a dedicated Ubuntu container (4 vCPU, 16 GB RAM) per interaction, where Gemini 3.5 Flash reasons in a loop until the task is done. A single interactions.create() API call kicks off server-side orchestration. This is Google's direct answer to Claude Code's sub-agent architecture — isolated execution environments as a first-class primitive, not an afterthought.

Antigravity CLI — containerized agents as the new CLI primitive ⚡

Workflow

With Gemini CLI retired on 18 June, Antigravity CLI is now Google's developer-facing tool. The key difference from a classic CLI: every command runs inside a dedicated Ubuntu container (4 vCPU, 16 GB RAM), so the agent can install packages, write files, and browse the web without touching your local filesystem. The model (Gemini 3.5 Flash) loops until the task is done. This matches the Claude Code sub-agent model architecturally — containerized execution, server-side orchestration, a single API call triggering a stateful run — and raises the floor for what "AI CLI tool" means in 2026.

§07 — Research Radar

Agent memory architecture is the most active research thread in June 2026 — three papers worth tracking, converging on the same problem: how do agents remember over long horizons without losing signal in retrieval noise.

Hierarchical Memory Orchestration for Personalized Persistent Agents

Method

arXiv 2604.01670. Proposes a layered memory system: short-term working memory, mid-term episodic summaries, and long-term semantic indexes — each with different retrieval strategies. The core finding is that flat RAG retrieval degrades sharply past ~200k tokens of context history, while hierarchical orchestration maintains performance. For the daily briefing pipeline specifically: if the briefing agent is running with multi-day context, hierarchical memory is the architecture that keeps earlier context addressable without context-window stuffing.

EverMemOS — a self-organizing memory OS for long-horizon reasoning

System

arXiv (January 2026). EverMemOS treats agent memory as an operating-system resource — with scheduling, eviction policies, and priority queues — rather than a static context window. The analogy is apt: just as an OS manages RAM across processes, EverMemOS manages memory across reasoning steps. The key primitive is "event-centric memory" — tagging stored observations by the event that generated them, not just semantic similarity, which improves retrieval precision for tasks that span days or weeks of agent activity. Directly relevant to the sub-agent pipeline in Claude Code where each sub-agent currently owns its own flat context.

State of AI Agent Memory 2026 — production gap report

Survey

mem0.ai's June 2026 production survey finds the largest gap between research and deployment is in persistent cross-session memory: 78% of surveyed teams handle this with ad-hoc database writes rather than a principled memory architecture. The survey identifies three production archetypes — append-only logs, vector RAG, and structured key-value stores — and benchmarks retrieval quality across them. Key result: for tasks requiring factual consistency across sessions (e.g., multi-day research agents), structured key-value outperforms vector RAG by 31% on a custom consistency eval. [paraphrased]
