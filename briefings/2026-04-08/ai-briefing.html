[Fundamentals]
Fundamentals: How Claude Code's Hook System Actually Works

Claude Code's recent defer permission feature (v2.1.89) built on top of the hook system — so understanding hooks unlocks what that feature actually means in practice.

What a hook is: A hook is a shell command (or script) that Claude Code automatically runs at specific points in a session — before a tool executes, after it completes, or when the session starts or stops. Think of them like database triggers, but for AI actions. You write a small script, register it in your Claude Code settings, and it fires automatically at the right moment.

The four hook events: PreToolUse fires before Claude runs any tool (file write, bash command, API call). PostToolUse fires after. Notification fires when Claude wants to alert you. Stop fires when the session ends. Each hook receives a JSON payload describing what's about to happen — the tool name, input parameters, session context.

What hooks can do: A hook can approve or block a tool call, modify its input, log it to a file, send a Telegram notification, write to a database, or — since v2.1.89 — "defer" it. Defer means: pause this tool call, save the session state, and wait for a human to resume with claude --resume. This is how you get genuine human-in-the-loop without breaking a long automated session — Claude stops at the sensitive step, you review the pending action, and approve or reject.

A practical example: You're running a Claude Code session to update a trading script. You write a hook that fires on PreToolUse for any Write tool targeting files in your live-trading directory. The hook checks the file path — if it matches /live/*, it defers rather than approves. Claude pauses, sends you a Telegram notification, and waits. You review the proposed file content and run claude --resume with approval. The session continues from exactly where it stopped.

Why this matters for the AI landscape: Hooks are the primitive that makes AI agents safe to deploy in sensitive environments. Without them, you face a binary choice: full automation (risky) or full human oversight (slow). With hooks, you can surgically insert human review only where it matters — before irreversible actions — while letting routine steps run unattended. As agents become more capable, the hook abstraction (or its equivalent in other frameworks) is what separates production-safe deployment from demo-quality automation.

⚡ Implication for dc: The defer feature is directly applicable to any Claude Code workflow that touches live systems — trading scripts, API integrations, Notion writes. Worth configuring a PreToolUse hook that defers writes to sensitive paths. Check the Claude Code docs for the anthropic/deferToolUse hook response shape.

Research Radar
AI Scientist-v2 automates scientific discovery end-to-end; Vero gives vision-language models a general-purpose RL training framework — both point toward AI systems that improve AI systems.
[Research] [Launch]
AI Scientist-v2 — Automated Scientific Discovery via Agentic Tree Search

AI Scientist-v2 introduces a workshop-level automated scientific discovery system using agentic tree search. The system can propose hypotheses, design experiments, run them computationally, interpret results, and write up findings — autonomously.

The "workshop-level" qualifier is important: this is not nature-paper quality yet, but papers generated by the system have passed reviewer thresholds at ML workshops. The agentic tree search architecture (rather than linear pipeline) is the key advance — it explores multiple hypothesis branches simultaneously and prunes dead ends without human intervention.

Why it matters in 6 months: AI-assisted research acceleration is real, but AI-automated research is qualitatively different. If this system can handle routine empirical ML experiments (ablations, hyperparameter searches, architecture comparisons), it compresses the research cycle for large labs dramatically — and raises the floor for what counts as a publishable contribution.

⚡ Monitor: No direct workflow implication today. Watch for adoption signals in ML labs — if major research groups start using AI Scientist-v2 for their own ablation studies, the pace of benchmark progress will accelerate further.
[Research] [Launch]
Vero (Princeton) — RL Framework for Vision-Language Model General Reasoning

Vero, from Princeton University researchers, is an open reinforcement learning framework for training vision-language models (VLMs) to perform general visual reasoning across diverse tasks. It addresses a key gap: current VLMs are strong on benchmark-specific tasks but brittle across task types. Vero uses RL to train for generalisation rather than benchmark optimisation.

Why it matters in 6 months: Gemini 3.1 Pro's benchmark dominance (including multimodal tasks) partly reflects Google's scale advantage in multimodal training data. A generalisation-focused RL framework like Vero could allow smaller labs to close this gap — and would make open-weight VLMs (Llama 4's multimodal layer, specifically) significantly more capable with modest fine-tuning.

⚡ Monitor: No immediate action. If Llama 4 Maverick adapters trained with Vero-style RL appear on HuggingFace in the next 4–6 weeks, that would be a concrete signal worth paying attention to.
