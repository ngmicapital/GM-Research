Research Radar

DeepSeek's "Thinking with Visual Primitives" paper integrates points and bounding boxes as units of thought into multimodal reasoning — a distinct architectural shift from chain-of-thought, with measurable gains on counting, spatial deduction, and topological tasks.

Thinking with Visual Primitives — DeepSeek-AI; points and bounding boxes as fundamental units of reasoning in MLLMs

ResearchDeepSeekVisual primitivesMLLM

DeepSeek-AI researchers introduced "Thinking with Visual Primitives" — a paper that integrates points and bounding boxes as fundamental units of thought into Multimodal Large Language Models (MLLMs). The architecture: instead of reasoning purely in text-token space about image content, the model produces structured visual primitives (a point at coordinate (x,y), a bounding box from (x1,y1) to (x2,y2)) as intermediate reasoning artefacts, the same way text-only chain-of-thought produces intermediate text tokens. The paper reports improvements on counting, spatial deduction, and topological navigation tasks, alongside significantly better visual token efficiency than the standard "describe the image in tokens, then reason in text" pattern that dominates current MLLM training.

⚡ Implication in 6 months: The "thinking in non-text primitives" frontier is where the next 12 months of multimodal research will move. For dc's Pengu Food Map work, this directly maps to a near-term real problem: identifying penguin-themed food items in user-submitted photos and reasoning about their location/category in a structured way. A Pengu Food Map MLLM that "thinks in bounding boxes and category labels" is much more useful for downstream queries (find all matcha desserts in Sydney CBD) than one that produces a free-text description. Not deployment-ready — code release pending — but the architectural direction is one to track, particularly if a Pengu Food Map vision pipeline gets scoped in Q2/Q3 2026.

Eywa framework — LLMs collaborating with modality-native scientific foundation models; +6.6% utility, −30% tokens, −10% time

ResearchEywaTool-useScientific FMs

The Eywa framework (recent arXiv) enables LLMs to collaborate with heterogeneous, modality-native scientific foundation models — models trained specifically on protein structures, climate simulations, materials, or genomics — rather than treating those domains as text problems. Reported on scientific benchmarks: ~6.6% improvement in task utility, ~30% reduction in token usage, ~10% reduction in execution time. The framing matters: Eywa is the first concrete workflow for "LLM as orchestrator of specialist models" in scientific domains, where the LLM understands the question and routes the actual computation to the right specialist FM (an AlphaFold variant, a climate ensemble, a chemistry model).

⚡ Implication in 6 months: The "general LLM + specialist model" pattern is starting to mature. For dc's biohacker pipeline (which currently uses Claude for everything from blood-panel interpretation to training-load analysis), the Eywa pattern suggests a future architecture: Claude as orchestrator, specialist models for the bio-research-specific calculations (protein interactions, biomarker reference ranges with proper Bayesian priors). Not deployment-ready in the consumer space yet — but if the bio-research plugin tier (which already includes scvi-tools, ChEMBL, ClinicalTrials) ever gets a dedicated foundation-model layer, this is the orchestration pattern it would use. Status: track.

🔬 Plain-English Explainer — what "open-weight 128B dense" actually means and why Mistral 3.5 matters

Modern AI models come in two architectural flavours. Dense models use every parameter in the network on every token they process — like having every cook in the kitchen work on every dish. Mixture-of-Experts (MoE) models like Kimi K2.5 only activate a subset of the network per token — like having 100 specialist cooks but only the 3 most relevant ones cook each dish. MoE is cheaper per query (only activate 3 cooks, not 100) but harder to fine-tune cleanly (you have to retrain the routing system). Mistral Medium 3.5 is 128 billion parameters, all of them dense — every parameter contributes to every output token. "Open weights" means Mistral has published the actual numbers that define the model on Hugging Face — anyone with sufficient hardware (4–6 H200 GPUs) can download those numbers, run the model locally, fine-tune it on a custom dataset, or modify the architecture. For traders, this matters in three concrete ways. First, if open-weight models continue to close the gap on closed frontier models (Claude, GPT, Gemini), the entire commercial-API revenue base of the frontier labs gets pressured — and that's the revenue base supporting the $852B OpenAI valuation, the $30B Anthropic round, and the $300B Q1 venture capital. Second, the AI-DePIN compute thesis (TAO, RENDER, AKT) gets stronger with each open-weight release, because a company running a fine-tuned Mistral 3.5 internally needs GPUs to host it — and those GPUs are exactly what DePIN compute networks rent out. Third, the dense vs MoE distinction matters for hardware demand: dense models use more memory bandwidth, MoE models use more compute. NVIDIA's H200 dominance is built around memory bandwidth — the more dense models matter, the more NVIDIA's moat holds. The Mistral 3.5 release is bullish for both NVIDIA and DePIN compute simultaneously, and bearish (slowly) for the frontier labs' pricing power.
