TL;DR — Driving Thesis

OpenAI and Cisco released Shirudo on 23 November, an open-source runtime that lets AI agents draft temporary eBPF shields for running Linux servers while permanent patches are tested. Two things to act on: pilot Shirudo only in test environments because it is pre-release, and review the approval policy before enabling Anthropic's new Claude Ship approval agents. Three to monitor: Akash's pending marketplace vote on moving to Solana, Z.ai's GLM-5.4 coding results, and Anthropic's share price after Cortex's 23 November issue reported a 5.3% Nasdaq fall on Friday.

Act on two things: first, Shirudo from OpenAI and Cisco is a real option for shielding running Linux hosts, but its repository labels it pre-release and production needs a patched kernel and TPM 2.0, so pilot it on non-critical hosts. Model Landscape

Open-weight releases from Chinese labs are setting this week's pace, while the closed US models arrive as version-number increments.

Z.ai ships GLM-5.4, its first Loop Transformer model

Z.ai released GLM-5.4 on 23 to 24 November, framed as a step toward generalised coding built on a loop-transformer architecture, which is the first of that design from the lab. The predecessor GLM-5.3 weights came out in August under a licence that is MIT-like but requires a Z.ai security review for hosts above $10B in trailing revenue. Independent coding results for GLM-5.4 were not available at time of writing, so treat any early claims as vendor figures.

Kimi K3.1 Pro: open weights, no published coding score

Moonshot's K3.1 Pro is a post-trained version of Kimi K3 with 2.8T total and 104B active parameters and a 1M-token context. The API launched on 23 October and the weights followed in early November; sources disagree on whether that was the 2nd or the 4th. On vendor-reported Terminal-Bench 2.1 scores, DeepSeek V4.1-Flash, Kimi K3 and GLM-5.3 lead the open-weight field at 90.6, 88.3 and 88.2, while K3.1 Pro has no published score yet.

Qwen4-Max and this week's closed-model releases

Alibaba's Qwen4-Max carries a 16 November date on Wikipedia, and Alibaba had previewed its 2.4-trillion-parameter Qwen3.8-Max in July with a promise to release weights. A daily agent-tools digest reports that OpenAI shipped GPT-6.2 Astra and Sol on 19 November and that Google launched Gemini 4 Neon, which that digest says ranks first on the Artificial Analysis Coding Agent Index at 58.6 on Google's own figures. That is a single secondary source, so confirm against vendor posts before citing.

OpenAI proposes shared development limits

OpenAI's chief scientist Jakub Pachocki published internal prediction-loss measurements on 22 November and proposed common development limits across labs. The post names cross-lab dataset differences and capabilities outside pretraining as open limitations. Read it as a research position rather than a product change.

Read-through: the frontier is moving on version numbers that most teams cannot benchmark in-house, so the open-weight leaders with published Terminal-Bench figures are the practical comparison set this week.

Claude Ecosystem

Anthropic's news this cycle is product surface, not capital: Claude Ship moves routine code approval into agents.

Claude Ship adds PR Steward and Claude Approvals in beta

Anthropic launched Claude Ship on Monday, a suite of agents for code review, fixes and approvals, according to a newsletter that cites TechCrunch. Code Review is generally available. PR Steward and Claude Approvals are in beta for Claude Team and Enterprise plans on GitHub. The approval policy is a plain-language file that the team writes, and teams still choose which changes escalate to a human reviewer.

Claude Code v2.1.331 adds Code Mode on cloud platforms

Claude Code v2.1.331 was published on 23 November at 21:34 UTC. It adds Code Mode in terminal sessions on Amazon Bedrock, Microsoft Foundry and other clouds, an API check inside claude doctor, and optionalDependencies support for plugins. For teams running Claude through a hyperscaler, this is the update that changes day-to-day workflow.

Post-IPO price: a follow-up, not new data

Cortex's 23 November issue reported a 5.3% Nasdaq fall on Friday as Anthropic gave back part of its listing-day gain. This issue has no fresh ANT price feed, so treat that move as carried forward from the earlier coverage. The Claude Ship beta and any GA date are the operational signals to watch.

Why it matters: an approval agent that acts on routine pull requests changes the review burden on engineering leads. Writing the policy file is now the control point, so it deserves the same review as the code it governs.

Decentralized AI

Decentralized AI is shipping infrastructure changes rather than price action, and the signals to track are migrations, utilisation and revenue claims.

Akash moves its token to Solana

Akash token holders voted on 2 November to move the network off its own Cosmos chain and onto Solana. A Solana version of AKT has been live since mid-November, but the marketplace switch still needs a further governance vote. Earlier Akash utilisation data showed 84 of 334 declared GPUs active in Q1, a gap that analysts describe as common across the sector.

io.net's burn promise is lagging its own revenue claim

io.net's Incentive Dynamic Engine, active since 11 June, promises to burn at least half of post-payout revenue in IO. Burns up to 19 November equalled 21.6% of block rewards. The $16.30M annualised revenue figure relayed by DePIN Pulse is io.net's own estimate rather than settled payments, so it should not be treated as audited income.

Render and Bittensor: usage counts and contested rankings

Render's foundation dashboard shows more than 82 million cumulative frames rendered and about 5,600 nodes since inception, while current active nodes were not disclosed. On 20 November CoinPaprika ranked Bittensor first at $1.79B and Render second at $709M, although Bittensor's classification as a DePIN project is disputed. Artificial Analysis added TAO, RENDER, AKT, FET and VIRTUAL to its AI watchlist when it revised its index on 27 October and published the list on 11 November.

Open-Source Pulse

Open weights from a Chinese lab and a medical-AI release lead the open-source cycle, while the developer signal is in local runtimes and new browser projects.

Ant releases LingSante open-weight medical models

Ant announced LingSante on 23 November. The line includes a Flash model with 560 billion total parameters, of which 25 billion are active per token. The release ships with research-use limits, which matter for anyone planning clinical deployment rather than evaluation.

Ladybird reaches its first alpha

Simon Willison flagged Ladybird's first alpha on 23 to 24 November. The project is a new browser written with its own HTML parser, CSS engine, layout and JavaScript components, which makes it a rare full-stack effort in 2026. It is an alpha, so expect gaps before any daily-driver use.

Local runtimes: Ollama and llama.cpp keep shipping

Ollama's stable 0.40.16 release is dated 9 November, and llama.cpp reached 0.9.0 on 4 November. Ollama also raised $65M in July on a user base near nine million, which gives it resources for the local-inference tooling most teams now standardise on. These are routine maintenance releases, so check changelogs before upgrading production hosts.

Workflow & Tools

Agent security is the new workflow category this week, led by an open-source runtime that lets agents write temporary shields for running systems.

Shirudo: agent-drafted eBPF shields for unpatched Linux

OpenAI and Cisco launched Shirudo on 23 November as an open-source runtime built on eBPF, which lets operators apply temporary protections to running Linux systems while a permanent patch is tested and rolled out. In a controlled Cisco test, a shield that OpenAI's Codex generated blocked an exploit attempt against a running Elasticsearch service without a restart. An operator approves each shield, and approved shields are signed, verified and logged before they run. The licence is BSD 2-Clause. The repository labels it pre-release, and production targets need a Linux kernel with Shirudo's patches, a signed-loader interface and TPM 2.0.

MCP: fixes and new servers

OpenCode v2.4.0 added a built-in desktop browser and fixed a case where MCP tool calls could hang for up to 30 minutes on malformed replies. Optional stdio MCP servers now start on their first tool call by default. Performativ launched its next-generation MCP for banks and wealth managers on 19 November, which is off until a firm enables it. By mid-2026, more than 10,000 MCP servers were reportedly in production.

OpenRouter removes providers and zero-retention endpoints

OpenRouter said on 22 November that it had removed three providers and withdrawn Zero Data Retention eligibility from 125 endpoints. Teams that route sensitive prompts through OpenRouter should check their endpoint list against the new eligibility before the next batch of requests.

Research Radar

Three papers from recent arXiv digests are worth tracking, though none has been replicated outside its authors' claims.

A CPU inside an LLM: compiling exact circuits into frozen weights

Tanmay Sah and colleagues propose zero-gradient circuit-grafting, which writes deterministic computation directly into the weights of a frozen LLM so that multi-digit arithmetic becomes exact without gradient fine-tuning [paraphrased from the digest summary]. If the method generalises, it offers a training-free route to reliability on symbolic tasks.

Mapping the AI supply chain

arXiv 2611.24927 maps dependencies, vulnerabilities and market concentration across the AI ecosystem. The digest lists it at title level only, so read the paper before drawing conclusions. It is relevant to anyone whose stack depends on a small number of model providers.

Anthropic's VP versus VNP claim

Anthropic's formal-math repository says an internal research Claude model discovered a result separating VP from VNP over every field. The README says the paper and its Lean 4 proof were written by AI models and that no human mathematician has yet checked the proof. It also states that the result does not settle P versus NP. Treat it as unrefereed until mathematicians have reviewed it.
