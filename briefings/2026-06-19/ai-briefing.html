§02 — Claude Ecosystem

Two flagships are still dark — but a restoration deal is now within days, and Opus 4.8 is carrying the load.

⚡ Update: Fable 5 / Mythos 5 — a deal is close

Regulatory Carry-forward

The shift since yesterday: this has moved from "indefinitely offline" to "actively negotiating a restore." Senior Anthropic technical staff met Department of Commerce officials in Washington on Monday, and MD-International Chris Ciauri said the company is "very confident that in the coming days, the models will become available again." Commerce Secretary Howard Lutnick framed the original concern as diversion risk — that the jailbreak could let the models be "deployed by or diverted to military and intelligence users in countries including China and Russia."

Anthropic's own statement (12 June) disputes the severity in plain terms: "The potential jailbreaks that have been disclosed to us are either entirely benign responses or are minor findings that provide no Mythos-specific uplift," adding that the capability "is widely available from other models (including OpenAI's GPT-5.5)." Its sharpest line is the precedent argument: "If this standard was applied across the industry, we believe it would essentially halt all new model deployments for all frontier model providers."

For positions: a restore in the next few days is the base case now, and it is bearish for the decentralised-AI token trade (see §03) — the entire rotation was priced on "governments can switch off centralised models." If they switch this one back on within ~10 days, the thesis loses its proof point.

Claude Code, week 24 — the resilience release ⚡

Workflow

The 8–12 June batch is unusually relevant given the week's events. New: fallbackModel configures up to three models tried in order if the primary is unavailable; --safe-mode (or CLAUDE_CODE_SAFE_MODE) launches with all customizations disabled — CLAUDE.md, skills, plugins, hooks, MCP servers — for clean troubleshooting; a /cd command moves a session to a new working directory mid-conversation without rebuilding the prompt cache; and sub-agents can now spawn their own sub-agents, with background chains capped at five levels deep.

Try this today: add fallbackModel to the scheduled briefing runs. The week's lesson is that a model you depend on can go dark on a Friday afternoon with no warning — a fallback to Opus 4.8 means the 6am brief still ships even if a primary is pulled.

Opus 4.8 is the unaffected workhorse

Status

Carry-forward, no change: Opus 4.8 was never in scope for the directive and remains the right default while Fable 5 is out. It already tops the Artificial Analysis leaderboard, so for most of Tony's tasks the shutdown is an inconvenience, not a capability loss.

§04 — Open-Source Pulse

Open weights are eating the frontier — and an open agent now claims to beat Claude Code on scientific reasoning.

Hugging Face "ML Intern" — an open agent that targets Claude Code ⚡

Open-source

Hugging Face released ML Intern, an open-source agent that autonomously researches, writes, and runs machine-learning code. Its pitch is benchmark-led: early results show it outperforming Anthropic's Claude Code on scientific reasoning and OpenAI's Codex on a healthcare evaluation. Treat the "beats Claude Code" claim as a vendor framing until there's independent reproduction — but the direction is real: open agents are now competitive on narrow, verifiable domains, not just chat.

DiffusionGemma — the parallel-decode bet, now adopted ⚡ carry

Open-source

Carried from yesterday with the spec nailed down: Google's DiffusionGemma (10 June, Apache 2.0) is a 26B-total Mixture-of-Experts that activates only 3.8B parameters per pass, and it generates over 1,000 tokens/sec on a single H100 — ~4× Gemma 4. Instead of left-to-right autoregression, it starts from a block of masked tokens and refines the whole block in parallel over a few passes. The use case is real-time, interactive UIs where latency matters more than peak reasoning — not a Claude/GPT replacement.

Holo3.1 — fast, local computer-use agents

Open-source

The Holo3.1 family (June) is built for on-device computer-use — robustness across environments (web, desktop, mobile), agent frameworks, and deployment targets. The interesting axis is "local": computer-use that runs without shipping every screenshot to a frontier API is the privacy-and-cost path for desktop automation, and it lines up with the resilience theme running through this whole issue.

§05 — Deals & Regulation

The export-control precedent is metastasizing into an EU sovereignty fight while the IPO pipeline goes vertical.

EU turns the export shock into a sovereignty push ⚡

Regulatory

The Fable 5 order produced the first documented head-of-government response from a US trading partner on AI-concentration risk, and it exposed a gap: there is no allied-nation exemption mechanism in current BIS rules. Brussels is now explicitly reframing reliance on US AI/cloud as a strategic vulnerability under its digital-sovereignty agenda. Sitting on top of that is the 2 August 2026 EU AI Act deadline, when most remaining provisions take effect — high-risk-system operators (including US firms) need to be compliant. The collision risk: a sovereignty-charged Brussels enforcing a major deadline six weeks out.

§06 — Workflow & Tools

This week's real product theme is resilience — the new features exist precisely because frontier access is now politically fragile.

Build for a model going dark

Workflow

The combination of fallbackModel (up to three models in order) and --safe-mode in Claude Code (§02) is the practical lesson of the Fable 5 episode made into config. The pattern worth adopting across any agent stack: never hard-code a single model dependency into a scheduled job. A primary → fallback chain turns "the model I rely on was pulled" from an outage into a quality dip.

Sub-agent chains, five levels deep

Workflow

Sub-agents spawning their own sub-agents (capped at five levels) is the orchestration unlock: a coordinator can now decompose a briefing run into per-section researchers that each spawn their own fetch/verify workers, without polluting the top-level context. For the daily briefing pipeline specifically, that maps cleanly onto "one agent per section, each owning its own sources."

Why "local computer-use" keeps showing up

Holo3.1 (§04) and the resilience features here point the same way: 2026's tooling is hedging against centralised dependency — on a single model, a single API, a single jurisdiction. The pattern to internalise is optionality. Anything mission-critical should have a path that survives one provider disappearing.

§07 — Research Radar

The literature is converging on one question: how do agents reason and improve over many steps, not one?

Agentic Reasoning for Large Language Models — the field's map

Survey

arXiv 2601.12538 (Wei et al., 18 Jan 2026). The reference survey for where agentic reasoning sits: it frames three layers — foundational agentic reasoning (single-agent plan/act), self-evolving agentic reasoning (refinement through feedback and adaptation), and collective multi-agent reasoning (collaboration). Not fresh this week, but it's the cleanest scaffold for reading everything else in this section, and it maps directly onto the sub-agent-chain tooling in §06.

Rethinking Agentic RL in LLMs — RL-PLUS

Method

arXiv 2604.27859. Proposes RL-PLUS, a hybrid-policy optimization framework that pairs internal exploitation with external data via Multiple Importance Sampling and an exploration-based advantage function. The relevance: post-training for long-horizon agent tasks is the lever everyone is pulling right now (it's also what GPT-5.6's "long-running agentic" claim in §01 implies under the hood), and this is one of the cleaner recent recipes for it.
