Memory poisoning extends to multi-agent systems ⚡

Research Security

The dominant 2026 agent-security shift — persistent memory as a first-class attack surface — now spans the multi-agent case. The canonical single-agent reference is "Memory Poisoning Attack and Defense on Memory-Based LLM-Agents" (arXiv 2601.05504); the new extension is "Memory poisoning and secure multi-agent systems" (arXiv 2603.20357), which categorises memory-system types, assesses poisoning feasibility per type, and proposes mitigations for multi-agent settings. Adjacent: MemoryGraft (arXiv 2512.16962) shows an attacker can supply benign-seeming artifacts during execution that get stored and later surface as malicious procedure templates on semantically-similar tasks, and a CODE "overthinking-attack" framework targets RAG-plus-reasoning systems with multi-agent-constructed poisoning samples that burn reasoning tokens without degrading accuracy.

⚡ So what: This is unusually on-point for dc, and more so this issue than last. The briefings-stack runs on a file-based persistent memory (the memory/ directory + MEMORY.md index), the harness already injects "recalled memories reflect what was true when written — verify before recommending," and Dynamic Workflows now makes the multi-agent case live in the stack. The take-home: keep treating recalled memory as evidence to verify, not instruction to follow; prune stale facts proactively (the consolidate-memory pass); and if a fan-out ever writes to shared memory, 2603.20357's multi-agent threat model is the one to read first.

Why "multi-agent" changes the memory threat

A single agent that poisons its own memory mostly harms itself. In a multi-agent fan-out (the Dynamic-Workflows shape), one subagent's poisoned or stale write can propagate to the orchestrator and to sibling subagents that read the shared state — so a bad memory entry becomes a blast radius, not a local fault. That is exactly why 2603.20357's per-memory-type feasibility analysis matters before wiring shared memory into any parallel briefing fan-out.
